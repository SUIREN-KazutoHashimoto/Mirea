# アップロードパイプライン

現行の詳細設計は[アップロードとジョブ](design/upload-jobs.md)へ統合しました。API形式は[分割アップロード](api.md#分割アップロード)、利用手順は[アップロード](user/uploads.md)を参照してください。

実装を変更する際に保つ条件は次のとおりです。

1. 分割受信が終わったら送信枠を解放し、次のアップロードを後処理待ちにしない。
2. 取り込み、表紙、変換、プレビューのレーンを分ける。同じアセットの依存順序は守る。
3. 音声／動画は原本公開後に再生可能にする。変換成功までは端末のコーデック対応に依存する。
4. 受信パートはhash・長さ・永続化を確認し、重複要求を安全に再送できる。
5. 元ファイルと保存先・シリーズの対応を送信開始時から維持する。
6. 再起動では永続状態から未完の処理単位を再実行する。プロセス内の待ち行列だけに依存しない。
7. 公開直前にも権限を確認し、削除／取消と競合した成果物を復活させない。
8. 完了したアセットの削除は未完送信の中止と分けて確認する。

実装の入口は[resumable.js](../server/resumable.js)、[media-pipeline.js](../server/media-pipeline.js)、[job-pool.js](../server/job-pool.js)です。
