# 0.20.0beta: 転送とメディア処理

アップロードの受信・原本準備・サムネイル・トランスコード・プレビューを分離しました。転送完了の応答後は、変換を待たずに次のファイルを送信できます。受信済みパーツはSHA-256で検証し、永続化してから応答します。同一パーツの再送では内容を検証しつつ重複書き込みを避け、ファイルが失われていた場合は再送で復旧します。

動画・音声は原本の形式検査と保存が終わると、指定した本棚・シリーズへ公開します。同じアセットではサムネイル生成、トランスコード、動画プレビュー生成の順です。異なるアセットは独立した待機列で並行処理されます。管理者の「転送・後処理の設定」で変更できます。

| 処理 | 初期同時数 | 上限 |
| --- | ---: | ---: |
| ユーザーごとの送信 | 3 | 32 |
| 原本の準備 | 2 | 8 |
| サムネイル生成 | 2 | 8 |
| トランスコード | 5 | 16 |
| 動画プレビュー生成 | 1 | 8 |

原本での先行再生は、そのファイルのコンテナ・コーデックを端末が再生できる場合に利用できます。対応していない場合は変換完了後に開き直してください。変換後は従来どおりH.264＋AAC、音声はAAC/M4Aです。先行再生のURLは原本を固定して参照し、変換完了で取得中のバイト列が変わることはありません。暗号化ダウンロードは変換後に利用できます。

原本を保持しない設定でも、すべての後処理が成功し、先行再生URLの期限が切れるまでは原本を削除しません。失敗時は原本を保持します。待機中・実行中の処理はDBへ記録し、サーバー再起動後に復旧します。処理中のアセットを削除すると、関連処理を停止してからファイルを整理します。

## プライベート本棚

Web/PWAでは、開くたびに本人のMireaパスワードを確認します。Androidではパスワード、または登録済み端末の強い生体認証を利用できます。端末の登録にはパスワードが必要です。生体認証はAndroid Keystoreの認証必須鍵で一回限りのチャレンジに署名し、サーバーが検証します。単なる成功フラグでは解除しません。生体認証が使えない端末はパスワードに戻れます。

確認許可はアカウントのセッションと本棚に限定し、別セッションへの流用・署名の再送・パスワード変更後の使用を拒否します。発行済み再生URLによるバックグラウンド再生は継続できます。サーバーは各配信時に現在の権限も確認します。

メタデータ・表紙の自動保存は継続します。オフラインでプライベート本棚を開くには、オンラインで一度パスワード確認が必要です。端末用のパスワード確認情報はPBKDF2で導出し、端末鍵で暗号化して保存します。Androidの生体認証も登録済み鍵の署名を確認します。ダウンロード本体の暗号化と、最後の接続から7日間の期限は従来どおりです。端末が侵害された場合まで保証するDRMではありません。

## 更新

DBスキーマ21では処理待機列と本棚確認用の表を追加します。既存のアカウント・メディア・履歴・暗号化鍵・証明書を変更しません。更新前にサーバーを停止し、data/media・設定・証明書をすべてバックアップしてください。新しい表を持つDBを旧サーバーで開かず、ロールバックは更新前の完全バックアップと組み合わせて行ってください。
