# 動画サムネイルのプレビュー

一覧の静止画サムネイルを、対象カードだけ短い動画へ切り替えます。動画本編の自動再生や全量取得はしません。PDF・画像本のサムネイルは静止画のままです。

## 表示のルール

- PC Webではマウスのホバーが350ms続くと開始します。キーボードでカードへフォーカスした場合も同じです。素早く通過しただけでは取得しません。
- Androidアプリとホバーできないタッチ端末では、スクロール停止後約180ms待ち、表示面積70%以上かつ中心が画面の中央20〜80%に入った動画カードから中央に近いものを選びます。650msの滞在後に開始します。横方向の位置も考慮し、小さな揺れで隣のカードへ頻繁に切り替えません。
- 同時に再生するカードは1件です。カード変更時は古い再生を止めます。スクロール中、画面外、ダイアログ表示、タブ非表示、ウィンドウ非アクティブでは停止します。AndroidではCapacitor AppのappStateChangeでも停止します。
- 音声はプレビューファイルに含めず、video要素もmuted・volume=0・playsinlineにします。短いクリップをループ表示し、本編の再生位置や音量設定には影響しません。
- prefers-reduced-motion、データセーバー、2g／slow-2gでは自動取得・再生を行いません。カードを開いて本編を再生する操作は通常通りです。
- 初回生成中は画像と「プレビュー準備中…」、再生開始後は「プレビュー · 音声なし」を表示します。自動再生が拒否された場合や生成・取得・再生エラー時は静止画へ戻します。操作が止まらないよう、プレビューの失敗でエラーダイアログは出しません。

無音・playsinlineと再生拒否時の静止画フォールバックは、ブラウザの[自動再生の案内](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)に沿ったものです。Androidの非表示検出は公式の[Capacitor App API](https://capacitorjs.com/docs/apis/app)を使います。

## クリップの生成と取得

サーバーがFFmpegで本編先頭から最大6秒を切り出し、H.264 / MP4、長辺最大480px、12fps、音声・字幕・チャプター・元メタデータなしへ変換します。最大2 MiBを超える出力は公開しません。本編は変更しません。

静止画は冒頭約2.5秒を12fpsで標本化し、最大30フレームから代表画像を選びます。短い動画では末尾までに得られたフレームだけを使い、1フレームの動画も処理します。固定秒数へシークしないため、動画の長さを超える地点を参照しません。動画プレビューも実際の長さが6秒未満ならその長さに合わせ、6秒への水増しはしません。

MP4の編集リストは通常どおり適用します。映像が1フレームも出力されない場合に限り、編集リストを無視する互換処理を1回だけ試します。元ファイルや本編の再生区間情報を書き換える処理ではありません。WebMにはこのMP4専用オプションを渡しません。通常処理と再試行を合わせた実行期限は30秒です。空のMP4コンテナだけができた場合も成功扱いにしません。

FFmpeg実行ファイルを起動できない場合と、動画から画像を取り出せない場合は区別します。メディア処理の内部エラー種別は、前者がサーバー設定の503、後者が映像フレーム・再生区間・対応形式を案内する422です。分割アップロードでは失敗状態と案内文を状態APIで返します。生成失敗の元の例外はサーバーログに保持し、利用者向けには内部パスやFFmpegの生出力を返しません。

生成は初回の対象選択時にだけ要求します。APIは短い202応答を返し、クライアントが状態を確認します。サムネイルと同じ直列メディア処理キューを使い、待機・生成中のプレビューは全体で最大4件です。同じ動画の並行要求は1件にまとめます。初回に時間がかかる場合は画像のまま待ち、約25秒を超える状態確認は打ち切ります。サーバーの生成自体は完了できるので、次回の選択時に使えます。

完成したクリップは `DATA_DIR/previews/<item UUID>.mp4` に保持し、再起動後も再利用します。失敗した生成は同じサーバープロセス内では5分間繰り返しません。再起動後は必要時に再試行します。中途の `.part.mp4` は通常の完了・失敗で回収します。強制終了で残る中途ファイルは、次回その動画を生成するときに置き換えるか、停止中にキャッシュとして回収します。

クライアントはBearer認証で小さな完成クリップを取得し、1件分だけBlob URLで表示します。ホバー解除・再描画・非表示・ログアウト等で通信を中断し、動画要素とBlob URLを解放します。セッションをまたぐブラウザキャッシュや永続保存はしません。すでに取得した内容を共有解除後に回収するDRM機能ではありません。

## 権限と削除

生成要求・状態確認・クリップ取得は毎回ログインと本棚所属を確認します。閲覧者も自分が見られる動画のプレビューを生成できます。本棚非所属は404、未認証は401です。動画以外のpreview要求は400です。クリップ取得はRange / HEADにも対応し、`private, no-store, no-transform` を返します。

item削除時に完成済みクリップを削除します。エンコード中の削除はDBを先に反映し、生成終了後にも存在を確認して中途・完成ファイルを回収します。プレビュー生成が失敗しても、本編と画像サムネイルは引き続き利用できます。

プレビューも動画配信に当たるため、Cloudflareの配信経路・利用条件は本編と同様に確認してください。[Cloudflare運用メモ](cloudflare.md)

## 検証範囲

実FFmpegを使い、音声付き8秒動画から音声なし・最大6秒・480×270のクリップを作ることを確認しています。生成の重複抑制、権限、再起動後の再利用、生成失敗時の画像維持、生成中削除の回収も自動テストします。

0.01秒指定の1フレーム素材、0.04秒・0.2秒・低fps・2秒の素材、WebM、正常な編集リスト、範囲外の編集リストを持つ合成MP4も自動テストします。分割アップロードからの公開と認証付きプレビュー取得、元動画のバイト一致、画像なし動画とFFmpeg未配置のエラーの区別を含みます。回帰素材は自動生成し、利用者の動画をリポジトリへ含めません。

フロント制御のテストではホバー滞在・スクロール停止・中央選択・同時1件・非表示／ダイアログ停止・設定尊重・通信中断・Blob解放を確認しています。Chromeではキーボードフォーカスからカード内の実再生（6秒・480×270・muted・loop・currentTime進行）と、フォーカス解除後の画像復帰を確認しました。実マウスホバー操作、Android実機のスクロール感・アプリライフサイクルの実機挙動は未確認です。
