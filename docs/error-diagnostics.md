# エラーの詳細とプライバシー

サーバー管理者ではないアカウントも、自分の操作で起きたエラーの診断情報をMireaの画面から確認できます。

1. エラーの表示後に「エラーの詳細を見る」を押します。確認・編集ダイアログの中からも開けます。
2. または「設定 → エラーの詳細を開く」を選びます。
3. 必要な項目の「安全な詳細をコピー」を押し、そのテキストをサポート担当者へ共有してください。作品一覧やTrueNASの詳細ログを渡す必要はありません。

## 表示する情報

- 操作の種類（シリーズ削除など。対象のID・名前・パスは含めません）
- 発生日時、HTTPステータス、サーバー／クライアントの版番号
- 許可リストにあるエラー種別・システムコード・SQLiteの数値コード・システム呼び出し名
- 予期しないサーバーエラーでは、既知のMireaソースファイル名と行・列番号（最大8フレーム、原因の連鎖は最大2段）
- サーバーの通常ログと照合するために、そのエラーだけに発行したランダムな照合ID

本文を正規表現で置換する方式ではありません。診断用の構造を許可リストから新規作成し、ブラウザー側でも再検証します。例外の原文・関数名・絶対パス・ファイル名・アセット名・本棚名・メール・ユーザー／アセットID・URL・クエリー・リクエスト本文・ヘッダー・トークン・Cookie・鍵・SQL・デコーダーの出力はコピー対象に含みません。未対応のエラーコードやフレームは省略します。

画像デコードの失敗では、許可済みの画像エラーコード・処理段階・形式・寸法・ページ番号と、既知のソース位置を表示します。通常の入力・権限エラーはソーストレースを表示しません。認証されていない要求にはサーバーの診断情報を返しません。他ユーザーのエラーを検索するAPIや、通常ログの閲覧APIは追加していません。

## 保持と共有

画面上の診断履歴は現在の画面のメモリ内に最大20件保持します。再読み込み・ログアウト・アカウント変更・サーバー変更で消えます。設定画面から手動消去もできます。LocalStorageやIndexedDB、端末ファイルには保存せず、自動アップロードもしません。コピーした場合はOSのクリップボードに残るため、共有後は必要に応じて消してください。

ログイン保持の通常の確認や、アップロードの順番待ち・自動再試行で回復した一時的な応答は通知しません。転送が最終的に失敗した場合に詳細を表示します。明示的なキャンセルや、以前のアカウントの遅れた応答は通知対象から除外します。

サーバーの既存の通常ログは従来どおりです。予期しないエラーのログに同じ`errorId`を追加するだけで、新たな生ログ公開・収集経路は設けません。認証や暗号化、TLS検証、ファイルのアクセス権は変更しません。

通信切断・古いサーバー・JSON以外のプロキシ応答など、サーバー側の安全なトレースを取得できない場合は、クライアント側の診断種別だけを表示します。ブラウザーやAndroid OSの生の例外ログを無条件に公開するものではありません。

## 画像書籍の後処理の調査

画像書籍で失敗した場合は「転送状況 → 要確認 → 詳細」を開いてください。対象ページとファイル名を本人の画面に表示します。「エラーの詳細を見る → 安全な詳細をコピー」には名前やパスを含めません。サーバー側ではアップロードの失敗時に安全な診断だけを既存の転送記録へ保存し、再起動後や本人の別端末でも確認できます。匿名・他ユーザーには返しません。過去版で失敗した転送には記録がないため、更新後に書籍を再度追加してください。

フォト等で表示できるJPEGでも、厳密なデコーダーでは拒否される場合があります。0.22.3はEOIマーカーだけが欠けたJPEGを一時コピーで補い、全画素を厳密に再検証します。原本を書き換えたり、破損検証を緩めたりはしません。実環境の報告がこの原因かは未確定です。引き続き失敗する場合は、安全な詳細を共有すれば対象画像を利用者が探し回る必要がありません。

## 更新時

データベース構造の変更はありません（schema23のまま）。更新前にdata・media・設定・証明書を一式バックアップしてください。Web/PWAはサーバー更新後の再読み込み、APKは同じ配布署名の新しい版への更新が必要です。古いAPKや古いサーバーには、診断表示またはサーバートレースの一部がありません。
