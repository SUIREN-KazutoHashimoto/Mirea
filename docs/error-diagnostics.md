# 安全なエラー詳細と診断送信

一般アカウントでも自分の操作の詳細を確認できます。操作手順は[困ったとき](user/help.md)、実装は[error-diagnostics.js](../server/error-diagnostics.js)、[許可リストschema](../server/error-diagnostic-schema.js)、[診断バッチ](../server/diagnostic-reports.js)を参照してください。

## 公開する構造

安全な診断は例外原文を加工した文字列ではなく、許可した値から新しいオブジェクトを組み立てます。

|項目|用途|
|---|---|
|schemaVersion|診断形式の版|
|errorId / occurredAt|このエラーだけのランダムIDと発生時刻。通常ログとの照合|
|status / operation / category|HTTP状態、操作分類、原因分類|
|code / type / sqliteCode等|許可済みコード・型・SQLite数値など|
|trace|既知のMireaソース名・行・列。最大8フレーム|
|causes|原因連鎖の安全な射影、最大2段|
|serverVersion / clientVersion|再現対象の版|
|image|許可済みの処理段階、形式、ページ番号／枚数、寸法|
|redacted|安全な形式に限定したことを示す|

例外原文、関数名、絶対パス、入力ファイル名、作品名、本棚名、メール、ユーザー／アセットID、URL、query、要求本文、ヘッダー、Cookie、トークン、鍵、SQL、デコーダー出力はコピー対象に含めません。未知のコードやフレームは省略します。クライアントでも構造を再検証します。

認証されていない要求にはサーバー診断を返しません。一般的な入力・認可エラーに内部スタックを付けず、必要なエラーだけで詳細表示を出します。HTMLのプロキシ応答や通信断など、サーバー診断がない場合にはクライアントの安全な分類だけを表示します。

## 保持場所と送信

画面の診断履歴はメモリー内に最大20件です。再読み込み、ログアウト、ユーザー／接続先変更で消えます。通常の一時的な再試行、明示キャンセル、古いアカウントの遅れた応答を新しい障害として通知しません。

失敗したアップロードの安全な診断は、サーバーの転送記録にも保存します。本人の別端末や再起動後にも確認できます。これを任意の通常ログ閲覧APIとして公開しません。本人の詳細画面には対象ファイル名を表示できても、安全なコピーには含めません。

利用者が「運営へ送信」を選ぶと、現在の安全な診断をPOST `/diagnostics/batches`でまとめて送ります。最大20件・128 KiB、毎分3回です。同じバッチIDで本人が再送したときは受領済みとして扱います。他人のバッチIDは409です。**自動で生ログを送信する機能ではありません。**

管理者はGET `/admin/diagnostics`で送信単位のバッチを閲覧・コピーします。応答は安全な診断を再検証した内容で、管理者用だから原例外が付くわけではありません。beforeによる過去ページ取得は最大100バッチです。DBの送信者関連付けと管理画面の表示項目は別です。

## 原因の分類

[media-failure.js](../server/media-failure.js)はデコーダー原文をサーバー内で分類し、公開用の固定メッセージにします。

|分類例|主な意味|
|---|---|
|ENOSPC / EDQUOT|一時領域または保存領域の容量／quota不足|
|EACCES / EPERM / EROFS|アクセス権または読み取り専用の保存先|
|ENOENT|入力や保存先が見つからない|
|IMAGE_TRUNCATED / IMAGE_INVALID_DATA|画像データの不完全・構造不正|
|IMAGE_PROFILE_INVALID|色プロファイルの解釈失敗|
|IMAGE_FORMAT_UNSUPPORTED / IMAGE_ANIMATED_UNSUPPORTED|対応する静止画像ではない|
|IMAGE_DECODE_FAILED|より具体的な分類ができないデコード失敗|

容量不足は画像破損と同じ扱いにせず503、入力そのものの不正は422等で返します。フォトビューアーで開けることだけでは、全画素の厳密なデコード検査やサーバーの空き容量を保証しません。

通常のサーバーログにはraw causeが残ることがあります。安全なコピーと通常ログを同じ公開範囲だと扱わないでください。サポートには最初に安全な診断を共有し、追加調査は合成データと隔離した検証環境で行います。クリップボードへコピーした内容はOS側に残る場合があります。
