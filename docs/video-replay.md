# 動画の長押しと再生頻度（0.4.3beta）

## 連続再生による採用条件（0.5.1beta）

グラフは再生開始・ジャンプ後に実再生時間が連続3秒に達した区間だけを採用します。倍速でもメディア時間でなく実再生時間の3秒です。到達時には保留していた最初の3秒分も含めて採用します。再ジャンプ、停止、バッファリング、ループ、終了、計測空白、位置／時間の不連続、イベント欠落で連続判定をリセットします。短い探索を複数回足して3秒とは判定しません。3秒未満の動画や短い再生には例外を設けません。

グラフ専用の派生テーブルanalytics_replay_bins／analytics_replay_state（DB15）を利用します。生イベント・従来のanalytics_video_bins・閲覧時間・本人のDL用ログはそのまま保存します。匿名5人の判定も、採用条件を満たした区間の閲覧者だけで行います。グラフの位置の重みは従来どおりメディア軸です。

APIの分割バッチを跨ぐ保留状態は永続化し、再送を二重加算しません。順序逆転で遅れて届いたイベントは対象セッションだけを再投影します。既存データもサーバー起動後に限定バッチでバックフィルし、元ログやlast_received_atを書き換えず、当日除外の条件をずらしません。再集計中は一時的にグラフが出ない／一部の履歴のみになる場合があります。派生計算の失敗で生ログ受信を巻き戻しません。Web／APKともサーバー共通のルールなのでアプリ更新は不要です。

## 表示条件の修正（0.4.4beta）

グラフはシークバーのノブを操作中だけ表示します。通常再生／一時停止／コントローラー表示／ホバー／動画の長押し2倍速だけでは表示しません。Webはポインター操作・シークキー・支援技術のinputを扱い、release/change/keyup/cancel/blur/画面非表示/PiP/再接続/closeで隠します。AndroidはSeekBarのタッチ追跡中に表示し、終了／取消／フォーカス喪失／回転／PiP／背景／画面非表示で隠します。表示切り替え時にノブが動かないよう、Androidはデータのあるグラフ領域をINVISIBLEで保持します（読み上げ対象外）。集計・本人限定表示・データ保存・権限は以下の従来仕様のままです。

動画の映像領域を長押しすると押している間だけ2×になります。Webは500ms、Androidは端末の長押し設定に従います。再生中のみ対象です。ボタン・タイムライン・音声には適用しません。離したときは元の速度（例1.25×）へ復帰し、一時的な2×を設定として保存しません。キャンセル・画面非表示・PiP・読み込み・シーク・再接続・再生終了でも復帰します。

`GET /api/v1/items/:id/replay-heatmap` はBearer認証と現在の本棚所属を確認する動画専用APIです。管理者にも生データは返しません。閲覧可能な動画の匿名化済み曲線のみを一般閲覧者にも表示します。任意の個人・期間フィルターは受け付けません。共通APIポリシーでCache-Control: no-storeを強制します。

通常のviewerセッションかつカウント対象に限り、各区間に5人以上を要求します。UTC当日開始以降に開始／受信があったセッションは全体を除外します。位置は最低10秒刻み、長い動画は最大200点になる固定幅へまとめます。各区間の実再生メディア時間から5回分単位で粗く丸めて正規化し、0.05単位の相対強度だけを返します。倍速・背景・PiPも実際に再生した位置の重みは同じです。生の回数・秒数・人数・ユーザーIDは返しません。

匿名グラフが成立しない場合は、認証中の本人のviewerセッションだけを集計し、scope:self／「自分の再生傾向」と明記します。当日分も含み、5人閾値や5回単位の丸めは不要ですが、位置は同じ固定幅、強度は0.05刻み、最大200点の相対値のみです。本人以外のデータは一切混ぜず、匿名曲線の空白へ本人の点を継ぎ足すこともしません。本人の記録がない場合は非表示です。画面を開く際に取得し、再生中にリアルタイム更新するものではありません。

グラフの欠けた区間は閲覧ゼロを意味せず、匿名化条件を満たさない場合もあります。グラフ全体が表示されない場合はデータ不足・集計停止・動画メタデータなしなどがあり、理由を細分化して個人の視聴有無を推測できる表示はしません。最も高い表示区間の開始位置をラベルにします。先頭の等高ピークを採用し、正確なリプレイ人数を表すものではありません。
