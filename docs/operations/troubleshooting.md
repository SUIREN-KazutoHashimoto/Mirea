# 困ったときの確認手順

症状に近い項目から確認します。再インストール、ブラウザーデータ消去、DB初期化は最初の対処にしません。端末保存や鍵が失われる場合があります。

対象: Mirea `1.0.0`。エラーの表示名は利用する版によって異なる場合があります。

## ログイン画面が開かない

1. サーバーが起動しているか確認します。Dockerなら次を実行します。

   ```sh
   docker compose -p mirea -f compose.release.yaml ps
   docker compose -p mirea -f compose.release.yaml logs --tail 60 mirea
   ```

2. URLの名前・ポート・HTTP/HTTPSを確認します。スマートフォンの `localhost` はサーバーPCではありません。
3. サーバーPCだけ開けるなら、公開アドレス、DNS、ファイアウォール、プロキシの接続先を確認します。
4. `/api/health` が開くのにUIだけ開かない場合は、サーバーのWebビルドとプロキシの配信設定を確認します。

ログ全文ではなく、時刻・Mirea版・起動失敗の原因行を絞って確認します。

## 証明書警告やAndroidの接続エラー

- URLのホスト名と証明書SANが一致しているか。
- leafとCAの期限、証明書チェーンが正しいか。
- 自分のCAを使う場合、対象端末が公開CA証明書を信頼しているか。
- プロキシがHTTPへ戻したり、同じURLへ無限リダイレクトしたりしていないか。
- Android用Origin `https://localhost` を許可しているか。

警告を無視する、TLS検証を無効化する、CORSを全面許可することで対処しません。[HTTPS手順](../install/https.md)

## コンテナがすぐ止まる

| ログの手がかり | 確認すること |
| --- | --- |
| `Landlock ABI >= 3 required` | 実行カーネルのLandlock対応と有効化。Desktopは内部VMの条件 |
| seccomp / capability / non-root | 標準seccomp、非root UID/GID、追加capabilityなし、既定Entrypoint |
| `MEDIA_DIR` identity / storage mode | 正しい保存先のマウント、data/mediaの対応、移行手順の実施 |
| ownership / permissions | 指定UID/GIDと実ファイル所有者、親ディレクトリ通過権限 |
| TLS fingerprint / receipt mismatch | 既存導入ID・証明書と設定の対応。受領情報を消さずバックアップと照合 |

起動保護は理由があって停止しています。特権化、`chmod 777`、識別ファイル削除、起動ランチャー迂回は行いません。[保護の条件](../container-security.md)

## 初期管理者でログインできない

`admin@example.com` / `ChangeMe` は空の新規環境だけの初期値です。既に変更済み、既存データを使用、別の保存先へ接続している場合は同じようにログインできません。

接続先URLと保存先を確認します。管理者情報を作り直すために既存DBを削除しないでください。一般利用者はサーバー管理者へ連絡します。メールによるパスワード再設定は提供していません。

## 設定画面で変更できない／再起動しても戻る

画面に「環境変数で上書き中」がある場合、その値が優先されています。Composeの `environment`、コンテナGUIの環境変数、OSサービス、`.env`の順に設定場所を確認します。UI管理へ戻す項目だけ指定を外し、サービスを再起動／再作成します。[設定の説明](settings.md)

## 送信は終わったのに作品が準備中

送信とサーバー側の後処理は別です。転送状況で受信が完了しているか、ジョブ管理で原本準備・表紙・変換・プレビューのどこまで進んでいるかを確認します。

原本が再生可能になっていれば、変換完了前でも開ける場合があります。原本の形式を端末が再生できない場合は変換が必要です。失敗した作品は原本を残して再試行できる場合があるため、先にアセットを削除しません。

ジョブがないのに準備中の表示が残る場合は、管理画面の未完了アセット修復を確認します。対象と理由を見て実行し、全作品を無条件に再変換しません。

## 画像・動画の処理が失敗する

| エラー | 主な確認先 |
| --- | --- |
| `ENOSPC` / `No space left on device` | data/media、一時領域、tmpfs、バックアップ領域の空き容量 |
| `EDQUOT` | データセット・ユーザーのクォータ |
| `EACCES` / `EROFS` | ファイル権限、読取専用マウント、実行UID/GID |
| 画像デコード失敗 | 安全な詳細のページ番号・段階。原本を保持し、そのページ単体でも再現するか |
| 処理時間超過・メモリー不足 | 同時処理数、高解像度画像、割り当てメモリー |
| FFmpegが利用できない | LinuxのOSパッケージ、設定パス、実行権限 |

ファイル容量と展開後の必要メモリーは別です。`/tmp`の上限を増やす場合は、ホストとコンテナのメモリー上限も確認します。容量不足は画像破損を意味しません。

## 保存した作品が外出先で開けない

1. 一覧・表紙だけでなく、作品本体のダウンロードが完了しているか確認します。
2. 同じサーバーURLとアカウントを使っているか確認します。
3. 最終認可から7日以内か確認し、接続できる場所で自動更新を待ちます。
4. サーバーで権限が解除されていないか、アセットが削除されていないか確認します。
5. 端末時刻、空き容量、ブラウザーのデータ削除・OSのストレージ整理の有無を確認します。

復旧前に端末保存を全削除しないでください。正常な保存データや未送信の続き位置まで失う場合があります。

## APK更新が見つからない

- サーバー自体が対象の公開版へ更新されているか。
- その公開版にAPKと署名付き更新JSONが揃っているか。
- サーバーから更新情報を取得でき、署名と期限が有効か。
- アプリの回線条件・閲覧中の保留・OSの提供元許可を満たしているか。
- 非公式／独自署名APKと公式APKを混ぜていないか。

Play Protectの有害判定と、更新JSONの期限切れは別の問題です。判定回避のために保護を無効化せず、公開版・端末・警告文を発行者へ伝えます。[更新の説明](updates.md)

## 問い合わせるときに送る情報

1. サーバー版とアプリ版。
2. Web/PWA/Androidのどれか、OSとブラウザーの版。
3. 実行した操作、期待した結果、実際の結果。
4. 画面の「エラーの詳細」または「安全な詳細をコピー」で得た情報。
5. エラー時刻。再現用データを用意できる場合は個人情報を含まない合成素材。

作品名、実ドメイン、IP、アカウント、絶対パス、Cookie、Bearerトークン、秘密鍵、`.env`全文は公開Issueへ貼りません。画像のブラウザーアドレス欄や通知にも注意します。安全な詳細は情報を絞っていますが、送信前に内容を確認します。[診断の範囲](../error-diagnostics.md)
