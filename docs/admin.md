# サーバー管理

サーバー管理者だけに「サーバー管理」を表示します。APIも毎回権限を検査します。本棚の所有者とサーバー管理者は別の権限で、サーバー管理者にメディア閲覧権を自動付与しません。

最初の管理者は `SERVER_ADMIN_USER_IDS` のアカウントUUIDで指定します。その後は管理画面で管理者／一般の変更、停止／再開、名前・メール変更、新規作成、削除ができます。DBの明示的な権限変更が環境変数より優先します。初期管理者のメールアドレスが同じというだけでは権限を付与しません。最後の有効な管理者の停止・解除・削除は禁止します。既存ユーザーのパスワードを管理者が既知の値へ変更して個人ログを閲覧する経路は作りません。パスワード変更は本人の設定画面で行います（新規作成時の初期パスワードは別経路で本人へ共有）。

認証情報・権限の変更時は対象の全セッションと配信チケットを失効させます。重要操作は管理者自身の現在のパスワードで再認証します。所有本棚のあるアカウントは本棚の所有者を先に変更します。共有アセットは削除せず、削除ユーザーとのアップロード者の紐付けだけを外します。管理操作は `admin_audit` に記録します（パスワード・個人の閲覧イベントは記録しません）。

## ジョブと再生成

- 既存アップロードの受信／変換段階・進捗・失敗、オンデマンド表紙／プレビュー処理、永続化した管理ジョブを表示します。表示は最新100件ずつです。
- PDF・画像本・EPUB・動画・音声の表紙、動画の短時間プレビューを再生成できます。失敗しても既存出力を残します。
- 動画の画質別MP4・HLSを再生成できます。保持原本を優先し、未保持なら基本MP4から再圧縮します。基本MP4自体・アセットID・続き位置・シリーズは変更しません。
- 配信世代を分け、旧HLSチケットと暗号化ダウンロードは旧世代を参照し続けます。旧世代はアセット削除まで保持するため、再生成するほどディスク使用量が増えます。元画質を超える復元はできません。
- 管理者は失敗した動画・音声アップロードを保存済み原本から再試行できます。アップロード者のアカウント有効性と本棚編集権、要求者の管理権限を再確認します。
- 再生成キューは上限20件、直列処理です。再起動後も再生成を再開します。単一プロセス／単一SQLiteボリュームで運用してください。

## 統計と本人の記録

管理画面の閲覧統計は従来どおり、5人以上・件数5単位・時間10秒単位・当日UTC除外の匿名集計です。アカウント管理と個人の閲覧ログを結び付ける管理APIはありません。

詳細な本人ログの表示画面は削除し、設定からNDJSONを最大1,000件ずつ取得します。記録・無期限保存は継続します。「閲覧履歴」は最近表示した作品名と日付だけを出し、現在アクセスできない作品は除外します。

## パスワード暗号化バックアップ

| モード | 含まれるもの |
| --- | --- |
| メタデータ | SQLite整合性スナップショット（アカウント、権限、シリーズ、進行度、詳細閲覧ログ等）、DATA_DIR内の暗号鍵、稼働アプリの `.env` があればその内容、設定／ファイル時刻マニフェスト |
| 全体 | 上記＋uploads（途中・失敗の転送原本を含む）、videos（旧配信世代含む）、originals、previews、thumbnails |

どちらにも機密情報を含みます。バックアップ画面で明示確認したうえで、管理者パスワードとは別の12文字以上のパスワードを指定します。scrypt（N=32768,r=8,p=1、ランダムsalt）で鍵を導出し、tar.gzをAES-256-GCMでストリーミング暗号化します。形式ヘッダーもAADで認証します。パスワードはDB・ディスクへ保存せず、再起動で中断したバックアップは作り直します。

作成中はAPI要求を一時制限して進行中の書き込みを排出し、メディア処理中は開始を拒否します。SQLiteは `node:sqlite.backup()` を使い、WAL中のDBファイルだけを単純コピーしません。シンボリックリンク等は追跡しません。暗号化前の一時DBはDATA_DIR内の非公開領域に置き、終了時に除去します。

OS・Node／pnpm等のランタイム、DATA_DIR外のTLS／CA秘密鍵、APK／更新情報署名鍵、専用更新ヘルパー設定、他のバックアップアーカイブは含みません。これらは別途安全に保管してください。メタデータのみではメディアは復元できません。

生成済みアーカイブは24時間保持し、管理者だけが取得／削除できます。PCの対応Chrome／Edgeでは8MiB Range転送でファイルへ直接保存します。AndroidアプリはOSの保存先選択（Storage Access Framework）を使い、ユーザーが選んだ1ファイルへ256KiBずつ書き込みます。追加の広範なストレージ権限や任意パスの読み出し機能は持ちません。その他のブラウザーは明示操作で8MiBずつ番号付き分割ファイルを取得します。大きなアーカイブ全体をブラウザーのRAMへ載せません。Androidで途中中断した出力は不完全なファイルとして残る場合があり、取得し直してください。

本人ログ・匿名集計のNDJSONもAndroidでは同じ保存先選択を使います。本人ログの出力は平文の機密ファイルです。共有先・保存先は本人が管理してください。Androidのファイル選択・保存は新APKのネイティブ機能を必要とし、実端末での操作確認は別途行ってください。

### 復号と復元

停止中の別フォルダーで復元を検証してから本番へ戻してください。本番への自動上書き復元APIは用意しません。

```powershell
node scripts/decrypt-backup.mjs --input=C:/secure/mirea-full.mireabackup --output=C:/secure/restore.tar.gz
```

パスワードは端末で非表示入力します。分割取得した場合は `--input=` を番号順の各ファイルに指定すると結合して復号します（名前でソート）。非対話では、アクセス制限したファイルを `--password-file=` で明示指定できます。パスワードをコマンドラインへ直接書かないでください。

GCM認証に成功するまで出力名を公開せず、パスワード不一致・改ざんでは平文出力を除去します。復号後は機密データなので保存フォルダーを保護してください。展開し `backup-manifest.json` とSQLite `PRAGMA integrity_check`／`foreign_key_check` を確認します。全体モードなら停止したMireaのDATA_DIRへ `data/` の内容を復元し、暗号鍵も必ず同時に戻します。`.env` の絶対パス・証明書パスは復元先へ合わせます。ファイル時刻が変わると、既存端末ダウンロードは整合性チェックで再取得を求める場合があります。

## WinVAI01直動作版の更新ヘルパー（初期設定は別途）

Webサーバーは引き続きLOCAL SERVICEです。管理画面から任意のコマンド・URL・パスを実行できません。Dockerソケットや管理者トークンをWebへ渡しません。コンテナの自己更新には未対応で、通常どおりイメージを外側から入れ替えてください。

管理者がレビュー済み配布版で、信頼するpnpm 11.25.0の配布ディレクトリを用意し、管理者PowerShellから一度だけ次を実行します。

```powershell
./scripts/Install-WindowsMaintenance.ps1 -PnpmDirectory C:/secure-tools/pnpm
```

`C:\ProgramData\Mirea\maintenance` を新規作成し、ヘルパー・設定はSYSTEM／Administratorsのみ書き込み可にします。WebのLOCAL SERVICEは `requests/` に要求を書けますが、`status/` とヘルパー本体は読み取りのみです。特権の `Mirea-Maintenance-v1` タスクが1分間隔で要求を確認します。既存フォルダーは上書きしません。

稼働版の環境に `WINDOWS_MAINTENANCE_DIR=C:/ProgramData/Mirea/maintenance` を設定して再起動すると更新実行ボタンが有効になります。未設定時も公式リリースの確認はできますが、更新を実行したふりはしません。

更新は固定リポジトリ `SUIREN-KazutoHashimoto/Mirea` の公開済みリリースだけが対象です。GitHub APIのasset ID／SHA-256／サイズをWeb側と独立したヘルパーで再取得し、ダウングレードやハッシュ未提供を拒否します。ダウンロード先とリダイレクトをHTTPSのGitHub配信ドメインへ限定し、展開前にtarのパス・リンク・重複・サイズ等を検査します。依存インストールは管理者でなくLOCAL SERVICEの一時タスクで実行します。

要求中は新規API操作を抑止します。ヘルパーが2分以内に応答しなければ要求を期限切れにし、API制限を解除します。ヘルパーは依存準備後にサービスを停止し、DATA_DIR全体のハッシュ照合済み退避と旧設定・タスク退避を作ってからリリースを切り替えます。更新中は利用停止になり、全データ量によって時間がかかります。新リリースのスキーマ移行はLOCAL SERVICEでの起動時に行います。証明書検証を有効にしたHTTPSヘルスチェックが失敗すると旧リリース・退避データへ戻し、失敗した新データは隔離して残します。

退避は `maintenance/rollback/` の管理者専用領域です。容量を監視し、復旧確認後に管理者が整理してください。タスクには30分の実行上限を設けます。依存準備・全データコピー・照合を含めて上限に達すると強制終了し、停止後であればサービス停止が残る場合があります。大容量環境は事前の所要時間測定が必須で、時間内に収まらない場合はこのヘルパーを有効化せず手動の更新手順を使ってください。ヘルパーが途中で強制終了した場合や復旧自体が失敗した場合は自動成功扱いにせず、タスク・`helper.log`・バックアップを管理者が確認します。ホスト実機での更新／ロールバック訓練後に有効化してください。

設計根拠: [Node.js SQLite Backup API](https://nodejs.org/download/release/v24.19.0/docs/api/sqlite.html#sqlitebackupsourceDb-path-options)、[GitHub Releases API](https://docs.github.com/en/rest/releases/releases?apiVersion=2022-11-28)。
