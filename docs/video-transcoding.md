# 動画の変換・画質選択・原本保持

新規動画はバックグラウンドでH.264（High / Level 4.1、8bit yuv420p、30fps）＋AAC（ステレオ48kHz / 128kbps）へ変換し、4秒単位のfMP4 HLSで配信します。無音の入力には無音AACを加えます。字幕・データ・添付画像・追加音声トラックは配信に含めません。動画の先頭6秒だけを使うプレビューとは別の本編データです。

Webの自前コントローラーから自動／1080p／720p／480p／360pを選べます。元の寸法以下の段階だけを生成し、360p未満は元寸法相当の1段階です。縦動画では枠の向きを入れ替え、縦横比を維持します。最大1080p相当で、4K／HDRの原画質を維持する方式ではありません。HLS.js対応ブラウザーでは同じvideo要素のまま自動／手動画質を切り替えます。ネイティブHLSでは手動切り替え時に位置を復元します。いずれも使えない端末では互換MP4へ戻り、画質選択を隠します。

CapacitorのWeb画面にも同じコードを使用します。すでに配布した旧APKの同梱画面には、新しいコントローラー／アップロード設定は自動配信されません。次回APKのビルド・配布と実機確認が別途必要です。旧APKから新規動画を送ってもサーバーの変換・初期OFFの原本保持方針は適用されます。

## 入力と制限

- MP4／M4V、MOV、MKV、WebM、AVI、WMV／ASF、MPEG、TS／MTS／M2TS、FLV。拡張子・申告MIMEだけを信用せずFFprobeと実デコードで検証します。
- コンテナ対応は内包する全コーデックへの保証ではありません。FFmpegで解読できない形式、音声のみ、DRM、外部プレイリストは拒否します。HDR（PQ／HLG）は色変換方針が未実装のため拒否します。
- 入力合計は既存のMAX_UPLOAD_BYTES（標準2 GiB）。長さ6時間以内、各辺8192px以内かつ約3355万画素以下のSDR。生成MP4は1画質8 GiBまで、画質別MP4＋HLSの作業出力は32 GiBまで。処理時間も1ジョブ6時間までです。限度に達した場合は公開せず失敗とし、原本を残します。
- 変換は1件ずつ。デコード／エンコード／フィルターを1スレッドに制限します。サムネイルは別の既存キューです。時間と容量の監視は1秒ごとで、OSレベルの厳密なCPU／メモリー／ディスク予約ではありません。公開サーバーではコンテナの資源制限と入口の制限も設定してください。

## 原本が消えるタイミング

アップロードの「動画の原本を保持する」は**初期OFF**です。次の全工程が成功するまで原本を削除しません。

1. ハッシュ検証済み分割の結合、入力解析。
2. 全画質MP4の変換、コーデック・寸法・長さ・全編デコードの検証。
3. 各画質のHLSマニフェスト／初期化ファイル／全セグメントの確認と全編デコード。
4. 画像サムネイルと短時間動画プレビューの生成。
5. 配信先への保存・ファイル同期・アクセス権の再検査、DBへの公開コミット。
6. コミット後に結合原本と受信分割を回収。保持ONの場合だけ別の原本コピーを残します。

保持ON/OFFはセッション作成時に固定し、ブラウザーの再開キーにも含めます。再試行で勝手に変更しません。変換／検証失敗時は結合原本と分割を無期限に残し、「アップロード処理」で本人が再試行または原本ごと取り消せます。処理中の正常停止・強制停止は、保持した分割から再起動時に再処理します。転送途中のセッションだけは24時間で期限切れです。受信途中に画面を閉じると取消、サーバー処理開始後に閉じると監視だけを終了します。

新規動画のプレビュー生成も必須工程なので、プレビューが失敗しても原本は残ります。保存領域自体の障害から保護するバックアップ機能ではありません。原本保持OFFの完了後には元の形式・解像度・複数音声・字幕等を取り戻せません。保持した原本の再変換／書き出しUIは未実装です。本の原本削除は行いません。

## 既存動画・認証・ダウンロード

更新前の動画はバイト列・UUID・再開位置・ダウンロード登録を変更せず、そのままRange配信します。既存原本の一括変換・削除は自動実行しません。新しい画質が必要なら原本を保持したうえで新規登録してください（別アセットになります）。

マニフェスト・初期化ファイル・各セグメントも、毎回セッション／本棚所属を検査します。チケットはアセットに限定され、最大1時間。閲覧中に更新し、再接続でも位置を維持します。ファイル名は生成済みの許可リストだけで、公開static配信しません。キャッシュはprivate / no-store / no-transformです。閲覧記録には選択画質・実画質・配信種別・帯域推定値を加えます。個人ログの閲覧権限・無期限保存方針は変更しません。

暗号化ダウンロードでは生成済みMP4の画質を選びます。端末内では1アセット1画質を保存し、変更時に旧コピーを置き換えます。サーバーの登録は画質別に維持するので、別端末の別画質は失効しません。AES-256-GCMの分割暗号化と、開く際のオンライン認可・メモリー内だけの復号鍵は共通です。ダウンロード上限は8 GiBですが、端末の実容量／ブラウザーの容量制限で失敗する場合があります。

## 運用と更新

直接起動・コンテナともDATA_DIR内で処理し、小さな/tmpは使いません。FFmpeg／FFprobeを依存として取得します。`FFMPEG_PATH`／`FFPROBE_PATH`で管理者が用意した絶対パスを指定できます。バイナリは依存ロックの版に固定されるため、運用者はFFmpegのセキュリティ更新を継続してください。

DATA_DIRの`videos/<UUID>/`はHLSと画質別MP4、`originals/<UUID>`は保持ONの原本、`uploads/<UUID>`は互換MP4です。`uploads/staging`／`uploads/transfers`は失敗・処理中ジョブの復旧に必要です。生成中は入力の複製、全画質MP4、HLS、互換MP4が共存し、最大設定では1件で40 GiB以上の空きが必要になります。空き容量予約・ユーザー別容量制限は未実装です。失敗原本を放置せず管理してください。

DB v11へ移行します。停止中のDATA_DIR全体（原本・派生ファイル・SQLite/WAL・keysを含む）と設定をバックアップしてから更新してください。v10のサーバーへ戻すには、旧コードと更新前バックアップを組で復元します。自動ダウングレードはありません。

HLSへの分割はCloudflareの動画／大容量コンテンツの利用条件を回避する仕組みではありません。[Cloudflare運用メモ](cloudflare.md)に従って配信経路を確認してください。
