# 画像書籍の容量不足（0.22.4beta）

JPEG等は圧縮容量と展開後容量が異なります。5197×7252・RGBの画像は、JPEGが20MiB以下でも展開すると約108MiBになります。従来のsharp.stats()はランダムアクセスで全画素の統計・ヒストグラム等を算出し、libvipsが一時ディスクへ展開します。コンテナの小さな一時領域ではwbuffer_write / No space left on deviceになる場合があります。

0.22.4は全画素を一度だけ順方向にデコードし、非圧縮・非インターレースPNGをnode:os.devNullへ直接書き出して破棄します。全画素の巨大JSバッファや検証用の展開画像ファイルを作りません。画像を縮小せずfailOn:warningの厳密検査を維持します。JPEG末尾補完のコピーも同じ検査を使います。元画像と既存データは書き換えません。

一時領域を増やしたり安全策・権限を緩めたりする必要はありません。ただし本来のdata/media領域の空き・クォータ不足は別です。ENOSPC（空き不足）、EDQUOT（容量制限）、EROFS（読み取り専用）を固定メッセージと安全な診断で区別します。例外原文・パス・ファイル名は共有用診断に含めません。

CIでは64MiBの/tmpで旧処理のENOSPCを再現し、合成画像106ページ相当の新処理・一時容量の非増加・破損拒否・表紙生成・原本同一性を検証します。TrueNASの利用者アセットを試験に使用しません。失敗済みアップロードの原本は公開前の失敗処理で残らないため、更新後に再追加してください。

参考: [sharp stats実装](https://github.com/lovell/sharp/blob/v0.35.5/src/stats.cc)・[libvipsの画像読み込み方式](https://www.libvips.org/API/current/How-it-opens-files.html)
