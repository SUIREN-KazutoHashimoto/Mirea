# 転送先と手動開始（0.25.0beta）

転送状況の各アップロードに「本棚 › 親シリーズ › 子シリーズ」を表示します。追加先を開くと、その本棚／シリーズのコンテンツ一覧へ移動します。移動・削除されたシリーズや権限変更は再確認し、プライベート本棚は通常どおり認証します。ファイルシステムのパスを公開する機能ではありません。

「送信待ち」の強制開始は、通常の同時送信数とは別の追加1枠です。追加枠はアカウントごとにサーバーが管理し、複数端末・複数タブで同時に押しても1件までです。受信完了後に解放され、後処理は通常のジョブ待機列へ入ります。送信元のブラウザー／Androidの転送サービスは、アップロード画面を閉じても開始依頼を受け取ります。ファイルを選択した端末が終了している場合は、その端末を開く必要があります。未開始の予約は90秒で解放されます。受信開始済みの項目は、既存の中止・再開・有効期限に従います。

管理者のジョブ管理でも、待機行の「強制開始」を使えます。通常のサムネイル・変換・プレビュー・取込などのレーン上限とは別に、管理者アカウントごとに同時1件です。実行時に管理者・アセット所有者・本棚権限などの既存チェックを行い、前処理依存や取消を省略しません。必要な先行ジョブが待機／実行中の場合、その先行ジョブから開始してください。修復全体を見守る調整用ジョブや、実行待ちではない処理には適用しません。追加枠は処理の完了・失敗・取消時に解放します。サーバー再起動後も本来の永続キューを復元しますが、ジョブの一時的な手動枠は引き継ぎません。

追加枠はCPU・メモリ・ディスク・回線の使用量を増やします。設定した通常上限は変更しません。アップロードとジョブの追加枠は別々です。
