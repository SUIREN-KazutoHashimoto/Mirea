# サーバーの設置方法を選ぶ

Mireaを使うには、作品を保存するサーバーを1台用意します。スマートフォンにAPKを入れるだけではサーバーは作成されません。既に接続先URLを案内されている利用者は、サーバーを新しく作る必要はありません。

対象は Mirea `2.0.0beta` です。配布物はGitHub Releasesで公開されているものを使い、そのリリースに添付された説明と組み合わせてください。

## 最初に選ぶこと

| 用意できる環境 | 読む手順 | 確認する条件 |
| --- | --- | --- |
| LinuxサーバーとDocker | [DockerとCompose](docker.md) | Linux/amd64、Landlock ABI 3以上、Docker標準seccomp |
| WindowsまたはmacOSのDocker Desktop | [Docker Desktop](docker-desktop.md) | Linuxコンテナを使う。内部Linux VMのLandlockとCPUアーキテクチャを確認 |
| TrueNASのApps | [TrueNAS Custom App](truenas.md) | DockerベースのApps。本書の画面名は25.04系を基準にする |
| WindowsまたはLinuxで直接起動したい | [Node.js直接起動](native.md) | Node.js 24、pnpm、メディア処理用ライブラリ |
| 別のDocker管理画面を使っている | [DockerとCompose](docker.md) | 同じイメージ・保存先・非root設定・起動保護を再現できること |

Docker Desktopが動くことと、Mireaの起動条件を満たすことは別です。起動時の保護に対応していない環境ではMireaは停止します。対応表にない機種や基盤の動作を保証するものではありません。

## 完了までの順番

1. **サーバーを起動する。** 上の表から手順を一つ選びます。
2. **初期管理者の情報を変更する。** 空の新規環境では `admin@example.com` / `ChangeMe` でログインし、自分のメールアドレスと十分に長いパスワードへ変更します。
3. **スマートフォン用の接続を用意する。** [HTTPSの手順](https.md)で、ブラウザーとAndroidが警告なしで接続できるURLを作ります。
4. **自分の作品を一つ追加して開く。** 小さなPDFや動画で、アップロード・表示・再生を確認します。
5. **バックアップを保存する。** [バックアップと復元](../operations/backup-restore.md)を読み、復旧に必要なものを揃えます。

初期管理者はユーザーが1人もいないDBだけに作成されます。既存環境でログインできない場合は、このアカウントを作るためにDBを削除しないでください。

## 保存先と必要な空き容量

サーバーの保存先には、原本だけでなく再生用の変換データ、表紙、転送途中のデータ、DB、バックアップが入ります。動画を多く扱う場合は、元ファイル合計の容量だけで判断しないでください。変換とバックアップに追加の空き容量が必要です。

小規模な試用では2 CPU・4 GiBメモリーを出発点にできますが、高解像度画像や動画の処理能力を保証する値ではありません。メモリーが少ない環境は[処理の同時実行数](../operations/settings.md)を下げて始めます。

DBとメディアを別ドライブへ置く場合は、最初に[保存先の分離](../storage.md)を決めます。既存データへ `MEDIA_DIR` を追加するだけでは移行できません。

## 迷ったとき

- サーバーのOS管理に慣れている場合はLinuxのDocker/Composeを使うと、起動設定と保存先を一つのファイルで管理できます。
- Docker Desktopの起動条件に合わないWindows PCは、Node.js直接起動を選べます。
- サーバーを外部へ公開する設定は、最初の導入に必要ありません。初期管理者の変更とHTTPS接続の確認を先に済ませます。
- バックアップや復元に不安がある場合は、まず少数のテスト用作品で一連の操作を確かめます。
