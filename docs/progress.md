# 続きから再生・閲覧

同じサーバー・同じアカウントで、PC WebとAndroidの間で最後に保存した続き位置を引き継ぎます。「最も遠くまで見た位置」ではなく「最後に保存した位置」なので、巻き戻し・読み直しも反映します。動画サムネイルのプレビューは対象外です。

## 動作

- 動画は再生時刻、本はページ番号・ページ内の縦横スクロール割合・選択倍率を、描画・メタデータ取得後に復元します。読み込み中の仮の先頭位置では以前の保存を上書きしません。
- 動画は自動再生しません。前回終端に達した動画は先頭から開き、単に開いて閉じただけでは終端到達状態を上書きしません。
- 本棚カードに本人の保存済み時刻／ページを表示します。「最初から」は0秒／1ページ目・幅に合わせる表示に戻します。分析用の過去ログは消しません。
- 約5秒ごと、一時停止・シーク完了・終了、閉じる、Webの非表示／ページ離脱、Androidのバックグラウンド移行で保存を試みます。本のスクロールと描画完了は端末へ即反映し、周期送信・終了時送信します。

スクロールはスクロール可能な範囲の0〜1の割合です。画面サイズが違ってもおおよその位置に戻せますが、文字・ピクセル単位での一致は保証しません。短いページは先頭です。進行度は視聴範囲・読了率の証明ではありません。

## 保存とプライバシー

SQLiteのasset_progressにアカウント＋アセットごと1件保存し、本人の現在の本棚所属を毎回検査します。本棚管理者・サーバー管理者にも、他人の再開位置を返すAPIはありません。一覧APIのprogressも本人だけです。DBを直接扱える運用者からの隔離は別の運用境界です。

分析ログと独立しており、ANALYTICS_ENABLED=falseでも保存します。保存期限は設けず、ログアウト・再ログイン・サーバー再起動でも維持します。共有解除後は取得／更新を拒否します。アセット／アカウント削除では関連する再開位置も削除しますが、無期限保存の分析ログは消しません。過去の分析イベントからの自動バックフィルはせず、導入後に開いたアセットから保存します。

## 通信失敗・同時閲覧

前回のrevisionとランダムなupdateIdを送信し、ビューアー内は直列更新・変更のまとめ送りを行います。直近の同一ID・同一内容の再送は二重更新しません。別端末・別タブが先に保存した場合は409にして、その画面からの保存を止め通知します。開き直すと最新位置を取得します。古いrevisionを強制的に読み替えないため、遅れた保存で新しい位置を巻き戻しません。「最初から」も同じ検査を行います。単一の共有プレイヤー制御ではなく、先に成功した保存を守る楽観的ロックです。

未送信位置はサーバー＋アカウント＋アセットで分離したlocalStorageに保持し、開いている間は約5秒ごと、また同じアセットを次に開いたときに再送します。トークン・メディアは保存しません。各アカウント／サーバーにつき直近200件・30日以内の未送信位置だけを残し、初期化時に古いものを回収します。ログアウトで残る場合があるため、共用端末の保存領域も管理してください。サーバーの保存済み位置に30日の制限はありません。

再送が競合した場合は古い未送信位置を破棄しサーバーを優先します。初回取得も失敗した場合、未送信位置があれば利用し、なければ先頭から開きます。通信復旧時に突然閲覧位置を移動せず、新たに閲覧した位置を保存します。端末の永続領域が使用不可・容量不足の場合はメモリ内だけで再送するため、閉じると未送信位置を失い得ます。

OS強制終了・電源断・通信切断時の最終位置の保存は保証できません。通常は約5秒の送信間隔があり、離脱時のBearer付きkeepalive送信もベストエフォートです。

## API

基点/api/v1、Bearer認証と現在の本棚所属が必要です。個人指定で対象ユーザーは変更できません。

| メソッド・パス | 内容 |
| --- | --- |
| GET /items/:id/progress | {progress,revision}。未保存はprogress:null・revision:0 |
| PUT /items/:id/progress | {revision,updateId,...position} → {progress} |
| GET /shelves/:id/items | 各itemのprogressに本人の保存済み位置／nullを追加 |

動画のpositionはpositionMs・durationMs（整数ms、0≦position≦duration、duration>0、最大31日）。本はpage（1始まり、実在ページ）、任意のscrollX/scrollY（0〜1、省略時0）、zoom（fit / 1 / 1.5 / 2、省略時fit）。形式混在は422、スキーマ違反は400、更新競合は409です。本文2 KiB・本人当たり毎分240回まで。

progressはrevision,positionMs,durationMs,page,scrollX,scrollY,zoom,completed,updatedAtを含み、無関係なフィールドはnull。completedは動画位置が終端に達したことだけを意味し、全区間を視聴したという意味ではありません。時刻はサーバー時計です。DBスキーマv6はv1〜v5のアカウント・メディア・分析ログを維持してテーブルを追加します。
