# メタデータ・アセットのリセット

「サーバー管理 → データのリセット」から、アカウントを残した全削除を実行できます。すべての利用者・本棚に影響します。通常のアップロード障害への最初の対処として実行しないでください。

## 削除するもの

- 本棚、共有／所属設定、シリーズ階層、アセットと表紙、原本・配信用ファイル・HLS・プレビュー。
- アップロード途中のファイルと失敗した原本、メディアジョブの記録・作業ファイル、残存メディア。
- 個人の閲覧記録・生ログ・集計・再生位置、再生チケット、暗号化ダウンロードのサーバー登録。

DATA_DIRとMEDIA_DIRを分離している場合も両方を対象にします。ただし指定されたルート自体は削除せず、アプリが管理するuploads/videos/originals/previews/thumbnails/admin-workだけを扱います。リンク・特殊ファイルを検出した場合は中止します。

## 残すもの

アカウントのID・メール・名前・パスワードハッシュ・サーバー権限・停止状態、ログインセッション、サーバー設定、保存先識別ファイル、ダウンロード暗号化マスター鍵、外部のTLS／CA証明書・秘密鍵・APK署名、既存バックアップとバックアップジョブ、更新設定と管理監査記録は保持します。バックアップ内には削除前のデータが残ります。これはディスクの安全消去ではありません。

## 実行手順

1. 全体バックアップを取得・保管します。TrueNASではApp停止中のDATA_DIR・MEDIA_DIR・設定の整合したスナップショットも推奨します。
2. メディアジョブの完了を待ち、転送中・閲覧中の利用者へ通知します。リセット中はAPI操作を停止します。
3. 削除する件数・ファイル数・容量を確認し、管理者パスワードと`RESET MEDIA AND METADATA`を入力します。対象確認は5分間有効で、同じログインセッションでのみ使えます。確認後にデータが変わった場合はやり直します。
4. 完了表示を確認し、本棚を作成し直します。リセットだけでストレージの権限不足・容量不足・マウント不良は直りません。

処理はメディアディレクトリを同じ保存領域内へ退避した後、SQLiteの一つのトランザクションで削除を確定し、退避ファイルを削除します。途中停止した場合はmedia-reset.jsonと監査記録から起動時に判定し、確定前なら元へ戻し、確定後なら削除を完了します。後処理エラー時は書き込みを止めたまま「未完了の後処理を再試行」で再開できます。復旧に失敗した場合はサーバーを停止してストレージを確認し、ジャーナルや退避ディレクトリを手動削除しないでください。

端末内のダウンロードは遠隔削除できません。再接続後は削除済みアセットにアクセスできませんが、オフライン中は発行済みの視聴許可が最長7日残る場合があります。

## アップロードエラーの確認

管理者ジョブとサーバーログの`Upload processing failed`を確認してください。`ENOSPC/EDQUOT`は容量・クォータ、`EACCES/EROFS`は実行UID（標準1000:1000）の書き込み権限・読み取り専用マウントを確認します。権限を全員へ開放したり、特権コンテナへ変更しないでください。

0.14.0以前の`ERR_INPUT_TYPE_NOT_ALLOWED`は、stdin/eval起動の`--input-type`がメディアワーカーへ引き継がれる不具合です。0.15.0へ更新すると解消します。通常は`node server/index.js`で起動し、TrueNASのCommand/Entrypoint上書きは不要です。失敗原本の保持と同時処理枠は別管理になり、失敗を3件残しても新規アップロードを妨げません。
