# メタデータとアセットを全削除する

対象: Mirea `1.0.0`。

「サーバー管理 → データのリセット」は、アカウントを残して全利用者の本棚・作品・記録を削除する操作です。管理者だけが実行できます。アップロードや変換のエラーを直す操作ではありません。

## 削除するものと残すもの

| 削除する | 残す |
| --- | --- |
| 本棚、共有・所属、シリーズ階層、アセット、表紙 | アカウント、パスワードハッシュ、サーバー権限、停止状態 |
| 原本、配信用ファイル、HLS、プレビュー、途中・失敗した転送データ | ログインセッション、サーバー設定 |
| メディアジョブの記録と作業ファイル、残存メディア | ダウンロード暗号化マスター鍵、保存先識別ファイル |
| 閲覧記録・集計・続き位置、配信チケット、サーバー側の端末保存登録 | 既存バックアップとバックアップジョブ、管理監査記録 |
| 対象データに付随する作品関係の情報 | 管理対象外の証明書・秘密鍵、APK署名情報 |

保存先が分離されていれば両方を対象にします。ただしルートディレクトリ自体は削除せず、アプリが管理する`uploads/videos/originals/previews/thumbnails/admin-work`を扱います。リンク・特殊ファイルは追跡しません。

バックアップには削除前の情報が残ります。これはディスクの安全消去や端末内データの遠隔削除ではありません。

## 実行前に準備する

1. [全体バックアップ](operations/backup-restore.md)を取得し、サーバーとは別の保護された場所へ保存します。
2. 復元できることを確認します。必要なら停止時点を揃えたdata/mediaと設定のスナップショットも取ります。
3. 転送・ジョブを終わらせ、利用者へ利用停止を伝えます。
4. 一部の本棚や作品だけを消したい場合は通常の削除操作を使い、全リセットを選びません。

## 画面から実行する

1. 管理者として「データのリセット」を開きます。
2. 対象件数、ファイル数、容量を確認します。
3. バックアップと端末内データの扱いを確認し、管理者の現在のパスワードと`RESET MEDIA AND METADATA`を入力します。
4. 実行し、完了表示を待ちます。
5. 本棚を作り直して、小さな検証用作品を追加します。アカウントと設定が保持されていることを確認します。

対象確認は5分間、同じログインセッションでのみ有効です。確認後にデータが変わった場合は、削除対象を確認し直します。

## 中断・エラーが起きたら

メディア領域を同じ保存先内へ退避し、SQLiteのトランザクションで削除を確定した後、退避ファイルを削除します。途中停止した場合は`media-reset.json`と監査記録から復旧状態を判定します。

- DB確定前: 起動時に元のメディアへ戻します。
- DB確定後: 削除の後処理を再開します。
- 後処理に失敗: 書き込みを止めたまま、画面の「後処理を再試行」で再開します。

解消しなければサーバーを停止し、保存先の空き容量・接続・所有者・権限を確認します。ジャーナルや退避ディレクトリを手動削除して状態を飛ばしません。復旧する場合は[コードと全データが対応するバックアップ](operations/backup-restore.md)を使用します。

端末内の暗号化ダウンロードは遠隔削除できません。サーバーへ再接続した後は削除済み作品にアクセスできませんが、オフライン中は既に発行された視聴許可が最長7日残ることがあります。

実装: [admin-reset.js](../server/admin-reset.js)。通常の障害調査は[トラブルシューティング](operations/troubleshooting.md)を使用してください。
