# 一覧の操作と端末設定

## 操作の配置

Web・PWA・Android内のライブラリは同じ `web/src/main.js` を使います。常設の操作は種類、タイトル検索、並び順、表示、内容検索、更新です。保存・表紙・タグ・解析・シリーズの一括管理は「一覧の操作」、シリーズ固有の編集は「シリーズの操作」へ分けます。

`library-panels.js` は非モーダルな重ね表示を担当します。同時に一つだけを開き、固定座標を画面端へ収めます。外側のポインター操作、Escape、画面幅変更、一覧の文脈変更で閉じます。スクロールでは起点に追従し、起点が画面外へ出た場合は閉じます。同じシリーズの再描画ではヘッダーのDOMを保持し、操作中のパネルを破棄しません。EscapeとAndroidの戻る操作では起点へフォーカスを戻します。Tabで外へ移動でき、モーダルのフォーカス制限やスワイプ取得は行いません。画面再構築とログアウト時にリスナーを解除します。

表示パネル内のselectは既存の `collection-view.js` を使い、一覧の再取得を必要としません。自動更新で内容が同じ場合のDOM維持は既存のカタログ処理を継続します。

## 並び順の保存

`collection-sort.js` が許可した値だけを保存します。保存先はブラウザープロフィール／アプリ導入先のlocalStorageで、サーバー同期はありません。キーは `mirea.library-sort.v2|` に、接続先・ユーザーID・一覧の種類とIDのJSON配列を続けます。単純な区切り文字の連結は使いません。

- シリーズIDがある場合、本棚IDをキーに含めません。同じシリーズへの入口や所属本棚の変更で設定を失わないためです。子と親のシリーズIDは別です。
- プレイリスト、本棚の直下、全コンテンツも独立した一覧です。検索文字と種類フィルターはキーに含めず、同じシリーズ内で並び順を共有します。
- 閲覧履歴は最後に閲覧した順を維持し、ソートの変更を無効にします。
- 新規シリーズ／プレイリストは保存された順、通常の一覧は追加が新しい順を初期値にします。既存のアセット順やDBの再生順は変更しません。
- 所有者を識別できない旧v1の全体キーは新しい利用者別キーへ自動コピーしません。アカウントが未確定ならスコープへ書き込みません。
- localStorageを使用できない場合も、同じ起動中はメモリー内で文脈別に保持します。保存失敗で一覧を停止しません。サイトデータの削除後と別のブラウザープロフィールは新規状態です。

画面遷移時は新しい文脈の設定を読み、シリーズを開くたびに設定順へ強制リセットしません。ブラウザー履歴にある古いsort値で現在の保存値を上書きせず、復元した文脈の設定を使います。

## 検証

`tests/collection-sort-context.test.js` でアカウント・接続先・端末・親子・本棚・プレイリストの分離と保存失敗を検査します。`scripts/check-library-controls-ui.mjs` は合成アカウントと一時サービスで、再読み込み、実際のアカウント切替、別ブラウザーコンテキスト、320/390px、パネルの重なりと位置、キーボード操作を確認します。これはAndroid実端末の成功を意味しません。
