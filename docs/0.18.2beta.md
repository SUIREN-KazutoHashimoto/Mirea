# 0.18.2beta

> 過去版の変更・検証記録です。現行の操作は[利用ガイド](user/first-steps.md)、設定と制限は[設定リファレンス](reference/configuration.md)、実装は[設計書](design/overview.md)を参照してください。

シリーズ配下の削除でSQLiteコード14（`SQLITE_CANTOPEN`）が出るコンテナの一時保存先の不整合に対応します。大きなストーリーボードなどを含む連鎖削除では、SQLiteの文単位のロールバック用ジャーナルがメモリーから一時ファイルへ移る場合があります。

従来、Unix VFSが`/var/tmp`を先に選択すると、ディレクトリのモード検査には通るのにLandlockが作成を拒否する場合がありました。新ランチャーは起動前に`SQLITE_TMPDIR=/tmp`を固定します。この修正のために導入先で変数を追加したり権限を変更したりする必要はありません。

- データベースのschema20と既存レコードは変更しません。DB本体とWALは従来のdataに保存し、一時ファイルだけが既存の許可済み`/tmp`を使用します。
- 非root・Landlock・seccomp・no_new_privs・TLS検証を維持します。`/var/tmp`への書込許可や、無制限のメモリー保存を追加する対処ではありません。
- 更新前にdata・media・設定・証明書を一式バックアップしてください。既存の導入ID・証明書・保存先・アカウントを保持してコンテナを更新します。
- Androidはcode37・0.18.2betaで、既存の専用署名を維持します。今回の不具合修正そのものはサーバーコンテナ側です。
- 合成データと隔離コンテナで検証します。
- すべてのコード14の原因を同一とは断定しません。更新後にも失敗する場合は「エラーの詳細を見る → 安全な詳細をコピー」で診断情報を共有してください。Play Protectの判定解除は確認していません。

根拠: [SQLiteのコード14](https://www.sqlite.org/rescode.html#cantopen)、[一時ファイルとUnix保存先の選択順](https://www.sqlite.org/tempfiles.html)。
