# 作品を追加して転送を確認する

追加先を決め、作品名と選択内容を確認してから送信します。アップロードは端末からサーバーへ送る処理です。表紙作成や再生用の変換は、その後にサーバーが行います。

> 対象は Mirea `1.0.0` です。[文書一覧](../README.md)

## 登録される単位を選ぶ

| したいこと | 選択方法 | 登録結果 |
| --- | --- | --- |
| PDF・EPUB・動画・音楽を追加 | 通常のファイル選択／ドロップ | ファイルごとに1作品 |
| スキャン画像を1冊にする | 通常のファイル選択で画像をまとめて選ぶ | 選択画像を順番にまとめた1冊 |
| フォルダ構造を保って取り込む | 「フォルダを丸ごと選択」 | フォルダはシリーズ、ファイルは個別作品 |

**フォルダ選択では、画像も1ファイルずつ別作品になります。** 複数画像を一冊にしたい場合は通常のファイル選択でまとめて選びます。拡張子だけを変更しても形式は変わりません。暗号化PDFやDRM付き電子書籍は対象外です。

## 一つ、または複数の作品を追加する

1. 「コンテンツを追加」を開きます。Web/PWAでは一覧へのファイルのドラッグ＆ドロップでも開けます。この操作だけでは送信しません。
2. 「追加する本棚」を確認します。編集権限のある本棚だけが選べます。
3. 必要なら「シリーズへの追加」で既存シリーズを選びます。新規の場合は名前と親を指定します。
4. 「動画・音声の原本を保持する」を確認します。初期状態はオンです。
5. ファイルを選ぶか選択枠へドロップします。
6. タイトルと選択一覧を確認します。画像本はページ順と先頭の表紙も確認します。
7. 「追加内容を確認」で追加先と同名候補を確認し、「確認した内容でアップロード」を選びます。

「ファイルを選び直す」は選択を変える操作です。開始済みの転送を取り消す場合は後述の取消を使います。

## 原本を保持する設定

原本は最初に選んだ動画・音声です。再生のために変換したファイルと区別して保存します。

- オンなら変換後も原本を残します。
- オフの場合だけ、必要な画質・表紙の生成と検証が成功した後に動画・音声の原本を削除します。
- 変換失敗時は原本を残します。
- PDF・EPUB・画像本の原本にはこのチェックを適用しません。

元の形式を将来も使いたい場合はオンにしてください。変換済みデータから、削除した元の動画・音声を完全には再現できません。

## 画像を一冊にまとめる

1. 通常のファイル選択でJPEG・PNG・WebPをまとめて選びます。
2. 数字を含むファイル名の順に並ぶ候補を確認します。
3. 選択一覧でページ順と表紙を調整します。
4. タイトルを確認して追加します。

最大1,000枚、1枚100 MiB以下の静止画像が対象です。合計はサーバーの1作品の容量上限以内にします。画素数の上限はありませんが、大きい画像の処理時間や必要メモリはファイル容量だけでは判断できません。

ページ原本は元の形式を保持し、サムネイルを別に生成します。失敗した場合は転送の「詳細」で対象ページと処理段階を確認します。

## フォルダをまとめて取り込む

次の例では `旅行` と `2025年` がシリーズになり、動画が中に入ります。

```text
旅行/
  2025年/
    01_出発.mp4
    02_街歩き.mp4
```

1. 追加先の本棚を選びます。
2. 既存シリーズの中へ入れるなら、そのシリーズを親として選びます。
3. 「フォルダを丸ごと選択」でフォルダを指定します。
4. 「アップロード候補を確認しています…」の間は待ちます。Androidでは保存場所の提供元によって探索時間が変わります。
5. 別のフォルダも入れるなら、選択を繰り返します。
6. 候補件数・対象外ファイルの件数・各作品の追加先を確認します。
7. 同名候補の扱いを決めて送信します。

空フォルダは登録しません。非対応形式などは候補から除く場合があるので探索後の件数を確認してください。一括選択は最大1,000ファイルで、管理者設定がそれより小さければその値が上限です。一度に扱うフォルダは最大300、シリーズは既存の親を含め最大16階層です。

同じ階層に同名シリーズが一つだけあれば、そのシリーズを使います。既存作品を削除・上書きしません。旧データに同名シリーズが複数ある場合は、手動整理するか候補から除外してください。

## 同名候補があるとき

Mirea 1.0.0の追加前確認は、追加先とタイトルで照合します。**名前が同じでもファイルの内容が同じとは限りません。**

| 選択 | 動作 |
| --- | --- |
| 既存をスキップ | 既存作品を変更せず、その候補を送らない |
| 別名で追加 | 提案された別名で新しく追加する |
| 対象から除外 | 今回の対象から外す |

まとめて指定することも個別に選ぶこともできます。追加・スキップ・除外の件数を確認して確定してください。確認後に別の人が作品を追加すると送信時に競合することがあります。その場合も既存作品を上書きしません。

## 送信完了と後処理完了を見分ける

```text
候補確認 → 送信待ち → 送信中 → 送信完了 → サーバーで後処理
                                            ↓
                                   表紙・再生用データ完成
```

送信済みの作品の変換を待たず、次のファイルを送ります。後処理はサーバーの待機列に入り、設定された数だけ並行します。

動画・音声は原本の準備後、変換途中でも原本で再生できる場合があります。端末がその形式を再生できる必要があります。暗号化ダウンロードや画質選択は、対応する再生用データができるまで利用できないことがあります。

| 操作・状態 | 継続できるか |
| --- | --- |
| アップロードのメニューを閉じる | 送信は継続 |
| 送信中にブラウザーのタブを閉じる・更新する・別サイトへ移動する | 中断する。離脱確認が出たら、継続したい場合は留まる |
| Androidで別アプリへ切り替える | 転送サービスで継続するが、OSの強制停止や制限を越える継続は保証されない |
| 全作品が送信完了・後処理になった | 端末を閉じても後処理はサーバーで継続 |

「送信が完了しました。変換などの後処理はサーバーで継続します」という案内を確認してから送信元を終了してください。

## 転送状況を使う

メニューの「転送状況」を開きます。フォルダ選択でも作品単位で表示します。

| タブ | 内容 |
| --- | --- |
| 進行中 | 送信・取得中と順番待ち |
| 要確認 | 失敗・中断・取消の記録 |
| 完了 | 終了した転送 |
| 後処理 | 送信後にサーバーが処理している作品 |

検索と転送種類で絞れます。「詳細」で対象ファイル・処理段階を確認し、「追加先を開く」で本棚やシリーズへ移れます。経過時間と終了見込みは速度や処理内容で変わる参考値です。

アップロードは同じアカウントの別端末からも確認できます。ただし、未送信のファイル実体は選択した端末にあります。別端末が代わりに送るわけではありません。ダウンロード状況はこの端末の記録です。

## 急ぐ一件を先に送る

「送信待ち」の「強制開始」は通常の同時送信数とは別の追加枠です。

1. 急ぐ作品の追加先と名前を確認し、「強制開始」を選びます。
2. 開始待ちのままなら、ファイルを選択した元の端末を開きます。

追加枠はアカウントごとに同時一件です。別端末・別タブで押しても増えず、受信完了後に解放します。権限や後処理の依存関係を省略する操作ではありません。

## 失敗したときに再開する

- **送信途中の通信失敗**：同じファイル・追加先・タイトルで再試行します。受信済み分割が残る24時間以内なら、照合後に続きから送れます。閉じた場合はファイルを選び直します。
- **一部だけ失敗**：元のアップロード画面の「未完了だけ再試行」で完了分を避けて再開します。
- **送信後の失敗**：「原本から再試行」があれば再アップロードせず後処理を再開できます。Mirea 1.0.0は画像本・PDF・EPUBの失敗原本も一定期間保持し、期限を表示します。
- **容量不足・形式エラー**：原因を解消してから再試行します。

取り込み成功前に端末の元ファイルを削除しないでください。保持期限を過ぎた失敗原本は、サーバーでの再試行に使えなくなります。

## 取消と記録のクリア

「アップロードを中止」は送信・後処理を中止し、受信済み原本も削除します。画面を隠す操作ではありません。完了作品も削除するかは別に確認します。

一括取消では、取り込みのために新規作成した空のシリーズを整理する場合があります。再利用した既存シリーズは、今回の追加先であるという理由だけで削除しません。

「要確認の記録をすべてクリア」は転送画面の記録を隠す操作です。アセットと保持原本は残ります。原本も不要なら、対象を確認して取消・削除してください。
