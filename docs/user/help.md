# 困ったとき

最初に、同じ接続先・同じアカウントを使っているか、今行いたい操作に権限があるかを確認します。アプリの再インストールやサイトデータの削除は、保存作品や未送信記録を失うため最初の対処にはしません。

> 対象は Mirea `1.0.0` です。[文書一覧](../README.md)

## ログイン画面が開かない

1. URLを末尾まで確認します。HTTPS、ホスト名、必要なポート番号の違いに注意します。
2. 同じ端末のブラウザーでもそのURLを開けるか確認します。
3. 証明書の警告が出る場合は管理者へ連絡します。警告無視や証明書検証の無効化で進めません。
4. サーバーを設置した人は[接続・運用のトラブルシューティング](../operations/troubleshooting.md)へ進みます。

一般のWebサイトが開けても、Mireaのサーバーへ到達できるとは限りません。自宅内だけで使う構成の場合、外出先から接続するための経路は管理者が用意する必要があります。

## 本棚や作品が見つからない

- 検索文字・種類・本棚・シリーズ・プレイリストの絞り込みを確認します。
- 「すべてのコンテンツ」へ戻ります。ただしプライベート本棚はここに出ません。本棚を直接開いて本人確認します。
- 更新アイコンで一覧を確認します。
- 共有されたはずの本棚なら、所有者に共有先のメールアドレスと権限を確認してもらいます。
- 通信できない場合、まだ端末へ保存していない最新の作品は表示できないことがあります。

作品のサムネイルが見えていても、本体を保存済みとは限りません。[保存の違い](downloads.md)を確認してください。

## 追加・編集・削除のボタンが使えない

閲覧者には作品の変更操作を許可しません。本棚の所有者に編集権限を依頼します。通信が必要な変更は、サーバーに接続できる状態で行います。

サーバー管理者でも、初期管理者のメールとパスワードを変更するまで管理操作が制限されます。設定画面の案内に従って両方を変更してください。

## アップロード候補の探索が長い

フォルダを選んだ後は、ファイル名・形式・階層を確認しています。画面に探索中の表示があればそのまま待ちます。特にAndroidのクラウドストレージなど、文書の提供元によって列挙に時間がかかります。

候補が出たら、件数と対象外ファイルの数を確認します。最大1,000ファイルを超える場合は複数回に分けます。中断したい場合にアプリを強制終了するより、選択画面のキャンセルを使います。

## 同じ名前という理由で追加できない

同じ本棚・同じシリーズ階層内で、同名の作品は追加できません。拡張子が違っても、Mirea上のタイトルが同じになる場合があります。

Mirea 1.0.0では追加前確認に候補を表示します。既存をスキップするか、別名を選ぶか、対象から除外します。既存作品を削除して解消しようとする前に、追加先の階層と表示タイトルを確認してください。

同名シリーズが複数ある旧データでは、追加先を自動で決めません。本棚の所有者・編集者が名前や階層を整理します。[取り込みの手順](uploads.md)

## 送信済みなのに「処理中」のまま

送信と表紙・変換・プレビュー生成は別です。「転送状況」の「後処理」で対象を確認します。大量の作品があるとサーバー側で待ちます。

原本で開ける動画・音楽は、変換が終わる前に再生できる場合があります。変換済み画質やダウンロードが必要なら完了を待ちます。

失敗と表示され、「原本から再試行」があれば再アップロードせずに試せます。待機が進まない、ジョブに見当たらない、再試行でも失敗する場合は、版と安全な診断情報を管理者へ伝えてください。管理者は[ジョブと運用](../operations/settings.md)を確認します。

## 画像・PDFの読み込みエラーになる

転送の「詳細」で、対象のページ・ファイルと処理段階を確認します。単に画像が壊れているとは限らず、サーバーの空き容量・一時領域・処理時間などでも失敗します。

1. 画像は1枚100 MiB以下、静止JPEG・PNG・WebPか確認します。PDFが暗号化されていないかも確認します。
2. エラーの詳細があれば、安全な詳細をコピーします。
3. 管理者へ、種類・容量・おおよその解像度・ページ数を伝えます。作品の全ファイルを送る必要はありません。
4. 原本が保持されている場合は、原因の解消後に「原本から再試行」を使います。

どのページか分からない場合も、書籍や原本を削除する必要はありません。失敗時の表示を残して確認を依頼してください。

## 保存済みの作品を開けない

1. 「設定」→「保存とオフライン」→「端末のダウンロードを開く」で保存状態を確認します。
2. 「未完了・再開可能」ならダウンロードを再開します。
3. 同じURL・アカウント・ブラウザープロファイル・APKで使っているか確認します。
4. サーバーへ接続できる状態で開き直し、許可を更新します。
5. プライベート本棚なら本人確認を行います。

最後の正常な権限確認から最長7日で期限が切れます。ログアウト、アカウント停止、共有解除でも利用できなくなります。端末データがOSやブラウザーに回収された場合は再取得が必要です。[保存と期限](downloads.md)

## 再生が止まる・バックグラウンドで中断する

- Web/PWAで音が出ない場合は再生ボタンを押し、消音・音量・ブラウザーの自動再生制限を確認します。
- 通信が不安定なら画質を「自動」または「データセーバー」にするか、事前に本体をダウンロードします。
- APKではメディア通知やPiPの許可を確認します。アプリの強制停止と、通常のホーム画面への移動は別の操作です。
- Web/PWAのタブ終了やOSのアプリ停止後まで、継続再生は保証されません。
- 生体認証やアカウントの失効で止まった場合は、権限を再確認してから再生します。

繰り返す場合は、端末とAndroid／ブラウザーの版、APKかPWAか、通信切り替えや画面操作の順を管理者へ伝えます。実際の作品を共有しなくても、まず操作手順で調査できます。

## アプリ更新が見つからない・インストールできない

1. 「設定」→「アプリと更新」で現在の版と更新状況を確認します。
2. サーバーへ正常に接続できる状態で確認します。
3. 転送・再生中なら、それらを終えてから再確認します。
4. Androidが確認操作を求めていれば、OSの画面へ進みます。
5. 更新情報が期限切れ、取得不能、署名不一致などなら、配布元またはサーバー管理者へ伝えます。

APKの署名が異なる場合は通常の上書き更新ができません。むやみにアンインストールすると保存作品と未送信情報を失います。Play Protectが有害として拒否した場合も、保護機能を無効にせず配布元へ確認してください。一般的なエラー表示だけでは、Googleの判定理由は特定できません。[更新の案内](../android-updates.md)

## エラーを伝えるとき

「設定」→「記録と診断」→「エラーの詳細を開く」、またはエラー画面の「エラーの詳細を見る」を利用します。安全な詳細をコピーするか、サーバーへの送信操作を選びます。

次の内容を添えると、作品を共有せずに調査を始めやすくなります。

- やろうとしたことと、実際の結果。
- 再現する操作の順番。
- Web／PWA／Android APKの別、端末・OS・アプリ／サーバーの版。
- 発生時刻と安全な診断情報。
- 毎回か、特定の通信状態や作品の種類だけか。

パスワード、秘密鍵、セッショントークンは送らないでください。一般の画面写真や詳細な閲覧記録は、マスクされた診断JSONとは異なります。作品名や共有相手が含まれないか確認します。

サーバー管理者向けの容量・証明書・コンテナ・復元の問題は、[運用のトラブルシューティング](../operations/troubleshooting.md)を参照してください。
