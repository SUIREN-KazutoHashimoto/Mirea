# 音声・音楽アセット（0.3.0beta）

音声を `kind: audio` として本棚に登録します。PC Web と Android は共通のアップロード・一覧・再生 UI を使います。0.2.3betaには含まれないため、Androidでは0.3.0beta以降の専用署名APKへ更新してください。

## 対応形式と配信

- MP3、M4A/M4B、AAC（ADTS）、WAV、FLAC、Ogg/Vorbis、Opus、AIFF、WMA、音声 WebM（`.weba`）。DRM付きは対象外です。
- 音声トラック必須、6時間以内、入力1〜8ch・8〜192kHz。映像トラック付きは動画としてアップロードします。埋め込みジャケットは映像本編とは区別します。
- FFmpeg/FFprobe で実内容を解析し、AAC-LC / M4A、48kHz、ステレオ192kbps（モノラル96kbps）に変換します。3ch以上は2chにダウンミックスします。ロスレス・ビットパーフェクト配信ではありません。
- `moov` を先頭に置いた M4A を認証付き HTTP Range でプログレッシブ配信します。全ファイルを先にメモリーへ読み込みません。音声のHLS・音質選択は現時点ではありません。
- 実行可能ファイル、変換キュー、スレッド数・時間・出力容量・許可コンテナ／プロトコルを制限し、出力の解析と全体デコード後だけ公開します。ネットワーク上のプレイリストは入力にしません。

FFmpeg の AAC エンコーダーと MP4 系コンテナの faststart を利用します。参考: [AAC公式ドキュメント](https://ffmpeg.org/ffmpeg-codecs.html#aac)、[MOV/MP4公式ドキュメント](https://ffmpeg.org/ffmpeg-formats.html#mov_002c-mp4_002c-ismv)。

## 表紙・操作

埋め込みJPEG/PNG/WebPジャケットがあれば縮小してサムネイルを生成します。ジャケットがない、対応外・不正な場合は専用の音符表紙を生成します。外部ジャケットURLは取得しません。失われたキャッシュ用サムネイルは配信原本だけで専用表紙に再生成できます。

音声タブ・件数表示・検索・シリーズ絞り込みに対応します。全画面の専用レイアウトに、再生／一時停止、10秒前後、シーク、音量・消音、速度変更、再接続を用意しています。カードの音声自動プレビューはありません。

再開位置・完了状態はアカウント別に保存します。シリーズの終了時は動画と同じく5秒後に次のアセットを開きます。自動再生の許可はブラウザー／OSの制約に従います。[PiP・バックグラウンド再生](background-playback.md)でAndroidの再生サービス・通知／ロック画面操作、WebのOSメディア操作を追加しています（開発中・未配布）。

## 原本・暗号化保存・記録

分割アップロードと処理中／失敗ジョブの再試行を動画と共通化しています。「動画・音声の原本を保持する」は初期OFFです。変換・サムネイル検証・ファイル同期・DBコミットが成功した後だけアップロード元を削除します。失敗した音声は期限で掃除せず、再試行または明示取消まで保持します。既存の本や動画の原本は変更しません。

端末内ダウンロードは他のアセット同様に AES-256-GCM の1MiB分割暗号化です。開くたびにオンラインで所属・セッションを再確認し、鍵は閲覧中のメモリーにだけ置きます。保存済みM4AもRange要求に合わせて必要な暗号化チャンクだけ復号します。

再生開始・一時停止・シーク・速度・音量・消音・再生区間を記録します。通常表示・PiP・背景再生の実再生を既存の `watchMs` と10秒区間 `videoBins` に格納し、`assetKind: audio` で動画と区別します（既存API名は維持）。バックグラウンド・PiPの実再生は専用フィールドで通常表示と区別し、飛び越えた区間や不明なタイマー停止は視聴時間に加算しません。音が実際に聞こえたことを保証する値ではなく、消音状態は生ログで確認できます。本人だけの詳細・無期限保存・管理者の匿名集計の権限境界は変更しません。

## 移行と運用

DBは11から12へ、音声のMIME制約と `audio_assets` を追加します。既存ID、共有、シリーズ、続き位置、暗号化ダウンロードの鍵／登録、生ログを保持し、既存メディアを再変換しません。通常の更新同様、停止中のDATA_DIRをバックアップしてから新サーバーを起動してください。

直接起動とコンテナで同じ実装を使います。Windows/macOSは既存の同梱FFmpeg、Linuxコンテナは既存のOS版FFmpegを使用し、明示した `FFMPEG_PATH` / `FFPROBE_PATH` が優先されます。追加サービスや新しい保存ボリュームは不要です。
