# 暗号化ダウンロード（オンライン認証必須）

0.2.1betaではEPUBにも対応します。EPUBは原本ZIPではなく、安全に変換した本文・挿絵を含む閲覧データを暗号化保存します。毎回のオンライン認可・メモリー限定の鍵・保存時暗号化は他形式と共通です。[EPUBの対応範囲と制限](immersive-epub.md)

通信の悪い場所に備えて、動画・PDF・画像の本を端末内に保存する機能です。完全オフライン機能ではありません。保存済みでも**開くたびに必ずサーバーへPOSTし、現在のログインと本棚所属を確認**します。接続できない・共有解除・ログアウト・アセット削除の場合は新しく開けません。前回の成功結果や保存済み鍵で認証を省略しません。

## 使い方

各カードの「暗号化ダウンロード」で開始します。閉じると一時停止し、同じアカウント・サーバー・アセットで「ダウンロードを再開」を選ぶと、検証済みの受信部分を再利用します。全分割がそろってから保存済みにします。保存済みアセットは開く際に端末のデータを優先使用します。

「端末のダウンロード」で保存状態を確認・開く・端末から削除できます。削除はその端末内だけで、サーバー原本や過去の閲覧履歴は消しません。破損・原本更新で開けない場合は、端末内データを削除して再取得してください。通常のオンライン閲覧にも戻せます。任意フォルダーへの平文PDF／MP4書き出しではなく、アプリ／ブラウザー内部の暗号化キャッシュです。

## 保存と暗号

1. サーバーがアカウント＋アセットごとのダウンロード登録と正規のファイル一覧を作成します。登録・取得時には復号鍵を渡しません。
2. 原本を1 MiB単位で読み、AES-256-GCM（128-bitタグ、毎回ランダムな96-bit IV）で暗号化して配信します。各パケットはIV 12 byte＋暗号文＋タグ16 byteです。AADで登録ID・ファイル番号・分割番号・平文長を認証します。別の本／ページ／区間への入れ替え、暗号文改ざん、鍵違いは復号に失敗します。[AES-GCMのIVと追加認証データ](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)
3. クライアントは暗号文の長さ・SHA-256を照合し、IndexedDBのmirea-encrypted-downloads-v1に暗号文だけを保存します。途中再開でもハッシュを確認します。アカウント・サーバーで管理領域を分け、未完了のデータは閲覧用に採用しません。
4. 開く際に毎回オンライン確認し、成功時のみ正規マニフェスト・今回のセッション期限・復号鍵を取得します。Web Cryptoへextractable:false、decrypt専用のCryptoKeyとして取り込みます。鍵・キー応答・平文メディアをIndexedDB／localStorage／Cache Storage／平文一時ファイルへ書く処理はありません。[Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)
5. 閲覧中のWindowのメモリーだけが鍵を保持します。Service Workerはその閲覧中Windowから、要求したクライアント固有の鍵をMessageChannelで受け取り、Rangeの必要部分だけを復号します。Workerには永続鍵やメディアのCache Storageを持たせません。Workerが再起動しても同じ閲覧中Windowがある場合だけ鍵を受け取れます。

IndexedDBにはタイトル・種別・ページ数・ファイル寸法・サイズ・暗号化形式・保存日時・内部ID等の管理情報は平文で保存します。保護対象は動画／PDF／ページ画像の本体です。サムネイル生成・通常のオンライン配信・サーバー原本の保存形式は従来のままで、サーバーの原本を暗号化する変更ではありません。ブラウザーの通常ダウンロードフォルダーに平文コピーは作りません。

動画全体を巨大な平文Blobへ展開せず、1 MiB単位の復号とReadableStreamのバックプレッシャーで配信します。単一Range、末尾Range、HEAD、シークに対応。PDF.jsも通常の256 KiB Range取得からこのローカル配信を使用します。画像本は選択した1ページを表示用Blobへ戻し、ページ移動・終了時にURLを解放します。復号データはメディアデコーダー／PDF.js／Canvas等のメモリーには存在します。

## アクセス権の境界

開いた時点の認可は閲覧を閉じるまで有効で、サーバーセッションの期限を超える新規復号は拒否します。閲覧中に毎秒サーバーへ確認する設計ではないため、最初の認証後に通信が途切れてもローカルの本体は利用できます。進行度と詳細ログは既存の送信待ち・再送処理を使います。アプリ画面全体を完全オフライン起動するためのキャッシュは作りません。

閉じる・ログアウト・サーバー／アカウント切替・ページ離脱で鍵参照とローカルURLへの許可を破棄します。Androidでアプリが非アクティブになった場合も、暗号化データの閲覧を閉じて許可を破棄します。戻って開くには再びオンライン確認が必要です。別タブ／別アカウントからローカルURLをコピーしても、そのWindowに正しい閲覧許可がなければ403になります。

**これは端末上の保存データの保護であり、DRMではありません。** 共有解除後の次回オープンは拒否しますが、すでに開いて復号したデータ・デコーダー内のフレームを遠隔回収する機能ではありません。開いたままの閲覧へ即時失効通知は送信しません。画面録画・開発ツール・改造クライアント・XSS・root端末・メモリーダンプ・ユーザー自身の保存操作まで防ぎません。ブラウザー内部のBlob／デコーダーの一時バッファやOSのスワップを含め、物理ディスク上に平文が一切残らないことや、GC／OSによる完全消去までは保証しません。公開運用ではHTTPSが必須です。

## 対応環境と制限

- Web Crypto・IndexedDB・モジュールService Worker・ReadableStreamが使える最新のPCブラウザー／Android System WebViewが必要。WebのHTTP接続（localhost開発を除く）や機能非対応環境では暗号化保存を拒否します。平文保存へフォールバックしません。
- AndroidはCapacitor 8のresolveServiceWorkerRequestsを有効にし、同梱アセットへのWorkerリクエストをブリッジ経由で扱います。通常リクエストはWorkerでキャッシュ・横取りせず、そのまま流します。[Capacitor設定](https://capacitorjs.com/docs/config)
- 元のコーデックを維持するため、動画が再生可能かは従来と同じ端末の対応状況によります。保存により未対応コーデックが再生可能になるわけではありません。
- 暗号化ダウンロードは1アセット8 GiBまで。各分割は1 MiB＋28 byte。画像本は既存の1冊500枚・1枚25 MiBの範囲です。空き容量を事前確認しますが、OS／ブラウザーの容量制限で途中失敗することがあります。
- サイトデータ削除・アプリデータ削除・ブラウザーによる保存領域回収で失われるため、端末のコピーは原本バックアップではありません。失われた場合は再取得します。
- 取得中に画面を閉じると一時停止します。バックグラウンド取得やOSのダウンロード管理への登録はしません。分割は最大3回再送、1要求のタイムアウトは60秒です。
- 開始／鍵発行はそれぞれ本人当たり毎分180回、分割は毎分600回まで。分割転送は同時に全体8件・本人2件に制限します。Cloudflareで暗号化しても既存の動画・大容量配信の利用条件を回避するものではありません。[Cloudflare運用](cloudflare.md)

## サーバーの鍵とバックアップ

初回起動時にDATA_DIR/keys/download-master.keyへ32 byteのランダムなマスター鍵を生成します。ディレクトリ0700・ファイル0600を指定し、個別の鍵はこのマスターと登録ID・アカウントID・アセットIDからHKDF-SHA-256で導出します。DBに個別の平文鍵を格納しません。WindowsではOS側ACLも管理してください。

**DATA_DIR全体、とくにkeys/download-master.keyをDBと同じ時点でバックアップしてください。** 既存の登録があるのに鍵を失った場合は勝手に新しい鍵を作らず、起動を拒否します。元のバックアップから復元してください。任意の新しい鍵への置き換え・鍵ローテーション画面は未実装です。通常の直接起動・コンテナ起動とも同じDATA_DIRを使用し、コンテナでは永続ボリューム内に保持します。サーバー管理者が原本・DB・マスター鍵へ直接アクセスできるという運用上の境界は変わりません。

## API

すべてBearer認証と現在の本棚所属が必要です。別アカウントの登録は本棚管理者でも取得できません。

| メソッド・パス（/api/v1から） | 応答 |
| --- | --- |
| POST /items/:id/download | {manifest}。鍵なし。原本が変わらない限り同じ登録IDを再利用 |
| GET /downloads/:id/files/:file/parts/:part | IV＋暗号文＋タグ。0始まり。X-Chunk-SHA256付き |
| POST /downloads/:id/open | 毎回認証・所属・原本の状態を確認して{manifest,key,expiresAt}。Cache-Control:no-store |

原本は登録UUID単位で不変という既存方針に加え、分割取得／オープン時にサイズ・更新時刻を照合します。原本の変更・欠損・削除時は拒否します。ファイル取得のI/O後や鍵発行直前にも認証・所属を再検査します。アセット／アカウント削除はダウンロード登録も削除します。端末内の暗号文は管理画面から除去できますが、登録が消えたデータへ鍵は発行しません。DBスキーマv7は既存の進行度・分析ログを保持します。


新規動画は画質別MP4を暗号化します。登録時に `{quality:"720p"}` 等を指定でき、省略時は最大画質です。端末内では1画質を保存し、画質変更時は旧コピーを置き換えます。サーバーでは画質別に登録IDを保持し、別端末の別画質は失効しません。既存登録ID／復号鍵の導出は変更しません。[動画の変換と原本保持](video-transcoding.md)
