# アセット閲覧記録

動画・音声・PDF・EPUB・複数画像の本を分析上は「アセット」と呼びます。既存APIの `items.id` と `assetId` は同じUUIDです。API名や既存メディアを破壊的に変更しません。WebとAndroidは同じ収集実装を使います。

## 誰が見られるか

| 利用者 | 個人別の詳細・生ログ | 集計 |
| --- | --- | --- |
| 閲覧した本人 | 自分のみ。ページ・区間・操作・時刻とNDJSON出力 | 自分のみ、時刻・アセット・本編／プレビューで絞り込み可 |
| 本棚管理者 | 他人の履歴は不可 | 現在管理する本棚内の匿名集計 |
| サーバー管理者 | 他人の履歴は不可 | アセット種別・本編／プレビュー・Web／Androidごとの全体匿名集計 |
| 編集者・閲覧者 | 自分のみ | 本棚全体や全体集計は不可 |

サーバー管理者であっても、本人用APIはその管理者自身の履歴しか返しません。管理者向けの生ログAPIはありません。管理者は `SERVER_ADMIN_USER_IDS` に登録済みアカウントUUIDをカンマ区切りで明示指定して、サーバーを再起動します。メールアドレスや「最初に登録した人」では自動付与しません。本人のUUIDは認証した `GET /api/v1/auth/me` の `user.id` で確認できます。Composeも同じ環境変数を渡します。

匿名集計は次の抑制を行います。

- 各出力グループに実閲覧した異なるアカウントが5人以上必要。ページ・動画の10秒区間も個別に閾値を適用。
- 件数は5単位、時間は10秒単位で切り捨て。5人が短時間見た場合、時間が0秒に丸まることもあります。
- 期間は7／30／90日・全期間のみ。当日（UTC 00:00以降）に開いたセッションを除外。
- 個人ID・表示名・メール・セッションID・個別時刻・個別イベントは出力しない。任意時刻・個人指定フィルターは拒否。
- 本棚内はアセット別・ページ別・区間別。全体は種別／本編・プレビュー／プラットフォーム単位のみで、アセット・本棚IDやタイトルも出さない。

これは少人数や細かい絞り込みによる推測を減らす措置であり、差分攻撃などに対する数学的な匿名性や差分プライバシーを保証するものではありません。本人用APIで公開する自分の記録と、管理者が別途知っている情報を組み合わせた推測も完全には防げません。

**この権限境界はアプリ／APIの境界です。サーバーOS、SQLite、バックアップを直接扱える運用者は、無期限保存する個人別の生ログを技術的には読めます。運用者からの隔離、本人だけが復号できる暗号化、鍵の分離は未実装です。** DB・バックアップのアクセス権、ディスク暗号化、運用監査は別途管理してください。生ログを個人別分析する外部サービスには送信しません。

## 記録する内容と数値の意味

イベントはschemaVersion 1。アセットを開くたびに新しい `viewId`、各イベントにUUIDと単調増加の `seq` を割り当てます。ユーザー・本棚・アセット種別・タイトル・ページ数はサーバーで解決し、クライアントのユーザー指定を信用しません。認証セッションのIDは保存しますが、Bearerトークン・再生チケット・パスワードは記録しません。GPS、フルURL、画面のテキスト、端末指紋、IPや生User-Agentを分析ペイロードとして収集しません（プロキシ等のアクセスログ設定は別です）。

| 項目 | 定義 |
| --- | --- |
| openedCount | 開いた閲覧セッション数。読み込み失敗も含む |
| viewCount | 実際にページを表示／動画再生を開始したセッション数。1セッション最大1回 |
| context | `viewer` が本編、`preview` が短時間サムネイル。必ず分離 |
| visibleMs | レンダリング済みコンテンツが画面内・アプリ前面に表示されていた推定時間 |
| activeMs | visibleMsのうちウィンドウがフォーカスされ、本・停止中の動画は約120秒の無操作放置に入っていない時間。再生中は操作がなくてもアクティブ扱い |
| watchMs | activeMsのうち停止・シーク・バッファ待ちでなく、動画の位置が妥当な速度で進んだ実時間。2倍速なら2秒分の内容でも概ね実時間1秒 |
| fromMs / toMs / rate | 動画のソース上の位置と速度。シーク操作は生ログに残すが飛び越えた区間は視聴に加算しない |
| videoBins | ソース上の10秒区間ごとのwatchMs／進んだmediaMs。境界をまたぐ場合は重なりで按分、繰り返しは累積 |
| endedCount | 終端に到達したセッション数。全編視聴率や完視聴の証明ではない |
| page / previousPage | 実際に描画できたページとページ遷移。読込中・描画失敗のページには滞在を加算しない |
| visits | 実際に表示したページへの入場回数。再拡大・再描画だけでは増やさない |
| x / y / width / height | ページ／動画領域を0〜1とした表示範囲。visibleRatioはその面積比。視線位置ではない |
| zoom / viewportWidth / viewportHeight | 倍率と表示領域寸法 |
| at / elapsedMs / receivedAt | 端末時計、セッション開始からの単調時間、サーバー受信時計 |
| arrivalDeltaMs | 受信時計−端末時計。通信遅延と時計のずれの両方を含み、単純な時刻補正値ではない |
| gapMs | スリープ等で計測間隔が延びた未計測時間。長い間隔は最大2秒だけ表示時間として扱い、実再生には加算しない |

主な操作イベントは open / view_start / interval / ready / play / pause / seeking / seeked / ended / rate_change / buffering / page_enter / page_loading / zoom / viewport / visibility / focus / idle / close / error / loop です。通常は約1秒間隔、スクロール後の表示範囲は約150msのデバウンスで記録します。イベント発生時にも前区間を確定します。単一閲覧セッションは最大7日で、以後の計測には開き直しが必要です。

読み込み完了や閉じる操作だけで「視聴した」と数えず、プレビューから本編に移動した場合も別セッションです。見えていたこと・アクティブだったことは、実際に読んだ／理解した／注視したことの証明ではありません。1秒の標本間の変化や短いループの巻戻りは厳密には復元できず、区間境界には誤差があります。クライアントが申告するイベントは改変も可能であり、料金請求・不正防止・厳密な監査証跡向けではありません。

## 送信と欠測

約5秒ごとに同じviewIdのイベントを最大40件・約58 KiB以内で送信します。API上限は50件・64 KiB、アカウント当たり毎分240リクエスト。Cloudflare用の巨大ファイル分割とは別の小さなJSON送信です。

ブラウザー／WebViewのIndexedDBにサーバー＋アカウントごとに未送信イベントを保存し、再接続・同一アカウントの再ログインで再送します。送信済みは端末から消します。認証情報やメディアはこのキューに保存しません。別アカウント・別サーバーの認証で古いキューを送信しません。複数タブが同じイベントを再送してもサーバーのUUID・viewId/seq・ペイロードハッシュによって重複加算しません。

未送信キューはアカウント＋サーバーごとに約10,000件を上限としてflush時に古いものから落とし、7日超は送信時／次のキュー初期化時に失効処理します。アプリを起動していない間に端末から自動消去するOSジョブではありません。IndexedDBが使えない場合はメモリだけになり、容量不足・強制終了・端末のデータ削除・キュー上限・共有解除・不正なイベントの拒否で欠測が発生します。未送信データはログアウト後も次回再送のために端末に残り得ます。共用端末ではサイト／アプリの保存領域も管理してください。

ネットワーク・429・5xxは指数バックオフ（最大約60秒）、401は同じ本人が再ログインするまで保持、403/404や形式不正・衝突のバッチは破棄します。pagehide時はBearer付きkeepalive送信を試みますが、OS強制終了時の送達保証はありません。送信失敗・キュー破棄は画面に非ブロッキングで通知します。メディアの閲覧自体は継続できます。サーバーで受理されたデータのみが永続履歴になります。

## 保存と大規模化

サーバーの生ログには保存期限を設けません。アセット削除・本棚共有解除・ログアウトでも履歴を消さず、本人は過去の記録を確認できます。ただし履歴から削除済み／共有解除後のメディアを取得できるわけではありません。自動消去・日数制限の設定はありません。0.2.0beta以降の本人による明示的な退会では、その人のviews/events/pages/video_binsを削除し、以後の匿名集計からも除外します。既存の運用バックアップや他端末の未送信記録は遠隔消去できません。[退会仕様](workspace.md)。`ANALYTICS_ENABLED=false` は新規の送信受付・クライアント収集を止め、保存済みの履歴と集計APIは維持します。

- `analytics_views`: ユーザー・アセット・本棚・種別・タイトルのスナップショット、端末区分、受信時刻、集計カウンター。元テーブルへのCASCADE外部キーを持たない。
- `analytics_events`: 全イベントの検証済みJSON、連番、イベントID、端末・受信時刻、重複照合ハッシュ。row_idがエクスポートカーソル。
- `analytics_pages`: 閲覧セッション・ページごとの滞在と回数。
- `analytics_video_bins`: 閲覧セッション・10秒区間ごとの実再生／ソース進行量。

受信・重複検査・ページ／動画区間集計を同一トランザクションで確定し、二重送信は再加算しません。生ログがあるため、後で区間幅や指標定義を変えて再計算できます。現状はSQLite・単一プロセス向けの収集基盤であり「ビッグデータ処理基盤が完成した」という意味ではありません。

1時間の閲覧につき約3,600のinterval＋操作イベントが増えます。イベントJSONの大きさ・インデックス・SQLiteページ使用率によって容量は変わりますが、数MiB／閲覧時間になり得ます。同時100人で1日8時間なら約288万interval／日なので、無期限運用ではストレージ増加・WAL・バックアップ時間・集計遅延を監視してください。性能上限の負荷試験は未実施です。必要に応じて収集DBをPostgreSQL等へ分離し、イベントキュー／バッチETL・Parquet・列指向分析DBなどを追加してください。その際も管理者に個別データを公開しない境界を維持します。

## API

認証は既存と同じBearer。個人用と管理者用で出力を明確に分けます。

| メソッド・パス（/api/v1から） | 内容 |
| --- | --- |
| POST /analytics/events | 本人の現在閲覧可能なアセットへイベントを送信。所属・形式・時間の整合性を確認 |
| GET /analytics/access | `{canViewGlobal}`。全体集計の閲覧可否 |
| GET /analytics/me/summary | 本人のみのアセット・ページ・10秒区間集計 |
| GET /analytics/me/events | 本人のみの生ログ、`after` カーソル・`limit` 最大1000・`format=json/ndjson` |
| GET /shelves/:id/analytics/summary | 本棚管理者の匿名集計 |
| GET /shelves/:id/analytics/export | 本棚管理者の匿名集計NDJSON。生ログではない |
| GET /analytics/global/summary | 指定サーバー管理者の全体匿名集計 |
| GET /analytics/global/export | 全体匿名集計NDJSON。生ログではない |

本人用フィルターは `from,to`（閲覧開始のepoch ms）、`assetId,context`。イベントは受信row_id順で `events,nextCursor,hasMore,schemaVersion` を返し、NDJSON時は `X-Next-Cursor` を返します。limit件ちょうどの場合はhasMoreがtrueで、次の取得が0件なら現時点の末尾です。末尾到達まで続けることで大きな履歴をメモリに全展開せず取得できます。UIの出力ボタンも1000件単位で続きから保存します。

本人集計の表示上限はアセット1000・ページ5000・動画区間5000、超過はtruncated=true。必要ならassetIdで絞るか生ログで再計算します。管理者集計も同じ上限とtruncatedフラグを持ち、期間（`period=7d/30d/90d/all`）と、本棚内だけアセット指定を受け付けます。匿名集計の全期間でも今日開いたセッションは含みません。セッション期間フィルターなので、日跨ぎの長い閲覧の時間を日別に切断した集計ではありません。

送信例:

```json
{
  "view": {"id":"00000000-0000-4000-8000-000000000001","assetId":"00000000-0000-4000-8000-000000000002","context":"viewer","platform":"web","clientVersion":"0.1.0"},
  "events": [{"id":"00000000-0000-4000-8000-000000000003","seq":1,"type":"interval","at":1700000001000,"elapsedMs":1000,"intervalMs":1000,"visibleMs":1000,"activeMs":1000,"watchMs":1000,"fromMs":0,"toMs":1000,"visible":true,"focused":true,"idle":false,"playing":true,"seeking":false,"buffering":false,"rate":1}]
}
```

応答は `{accepted,duplicates,schemaVersion}`。同一ID・同一内容の再送は受理済みとして成功、内容違いは409、重なる区間・不可能なページ／時間等は422。バッチの不整合は全件ロールバックします。生ログのイベント型とフィールドの最終定義は `server/analytics.js` のスキーマを参照してください。

音声は `asset_kind: audio` として動画と区別します。再生区間の集計先は互換性のため既存の `videoBins` / `analytics_video_bins` を共有します。収集・時間の定義・匿名集計の条件は動画と同じです。[音声対応の詳細と制限](audio.md)も参照してください。
