# Mirea

このソースは **0.2.3beta**（内部バージョン `0.2.3-beta`、Android配布版versionCode 4）です。[専用署名APK・サーバーパッケージ](https://github.com/SUIREN-KazutoHashimoto/Mirea/releases/tag/v0.2.3beta)、[起動手順・ベータの制限](RELEASE.md)、[設定・アカウント・全画面ビューアー](docs/workspace.md) を参照してください。旧デバッグ署名APKからの初回移行は手動です。

動画・音声・音楽・PDF・EPUB・複数画像の本を、本棚単位で共有できるクライアント・サーバー型メディアライブラリです。PCのWebブラウザとAndroidアプリが、同じAPI・アカウント・本棚を使います。

0.2.1betaでは[コンテンツ優先の没入表示・スワイプ改善・EPUB対応](docs/immersive-epub.md)を追加しています。DRMなしのリフロー型EPUB 2／3を対象とし、章の目次・文字サイズ・続き位置・表紙・暗号化ダウンロードに対応します。固定レイアウト、MOBI／AZW／CBZ／CBRは対象外です。

0.2.2betaでは[動画の画質選択・H.264＋AACへの変換・原本保持の選択](docs/video-transcoding.md)を追加しています。新規動画の原本保持は初期OFFで、全工程が成功した後にだけ原本を削除します。既存動画の自動変換・削除はしません。

0.2.3betaでは[ストア外Androidアプリの署名付き自動更新](docs/android-updates.md)を追加しています。自動確認・非従量制回線での取得・閲覧中の保留・OS確認への案内に対応します。旧デバッグ署名から専用署名への初回移行だけは手動です。

音声・音楽アセット対応を作業ブランチで開発中です（**未配布・LAN未反映**）。[対応形式・配信・原本保持・制限](docs/audio.md)を参照してください。

[動画のPiP／動画・音楽のバックグラウンド再生](docs/background-playback.md)も開発中です。Webの背景再生バーとOSメディア操作、Androidの独立した再生サービス・通知／ロック画面操作を追加しています（未配布）。

## 現在の機能

- アカウント登録、ログイン、ログアウト
- 複数本棚の作成、所属する本棚だけの一覧・閲覧
- 本棚とアカウントの多対多の関連付け
- 本棚内のシリーズ管理（PDF・画像本・動画の混在、巻・話ラベル、並べ替え、シリーズ絞り込み、閲覧中の前後移動）
- シリーズ連続再生・閲覧（動画終了後5秒で次へ、本は最終ページの次操作で次の作品へ。ON/OFF・カウントダウン取消付き）
- メールアドレスで登録済みアカウントを追加、権限変更、共有解除
- クライアントからのPDF・EPUB・MP4／MOV／MKV／WebM／AVI／WMV／MPEG／TS／FLVアップロードと進捗表示
- 標準8 MiBの分割送信、通信失敗時の再送、24時間以内の続きからの送信
- サムネイル生成を非同期処理し、完了状況を短いAPIリクエストで確認
- JPEG・PNG・WebPの複数画像を1冊として登録（1枚から可）
- 画像の本のページ順プレビュー・並べ替え・ページ移動・拡大表示
- PDFは1ページ目、画像の本は先頭ページ、動画は抽出フレームをサムネイルとして表示
- 動画カードはPCのホバー／キーボードフォーカス、Androidのスクロール停止後に画像から無音プレビューへ切替（同時1件、最大6秒のループ）
- PDF.jsによるアプリ内PDF表示（256 KiB単位の必要範囲取得・ページ移動・倍率変更・日本語フォント対応）
- H.264＋AACの複数画質HLSストリーミング、画質選択、互換MP4／既存動画のRangeシーク
- アカウント別の続き位置保存。動画は再生時刻、PDF・画像本はページ／スクロール位置／倍率をWeb・Android間で引継ぎ
- PDF・画像本・動画の暗号化ダウンロード／中断・再開／端末内の保存管理。開くたびにオンラインで権限確認
- アセットの詳細閲覧記録（ページ・表示範囲・時間・再生区間・操作、プレビュー別集計）、生ログの無期限保存
- 本人だけの詳細履歴／NDJSON出力、本棚管理者の本棚内匿名集計、明示指定したサーバー管理者の全体匿名集計
- タイトル検索、種類の絞り込み、並び替え
- Node.jsによる直接起動と、Docker Composeによるコンテナ起動の両対応
- CapacitorによるAndroidアプリ用プロジェクト

| 本棚での権限 | 閲覧 | アップロード・削除 | メンバー管理 |
| --- | --- | --- | --- |
| 管理者（作成者） | ✓ | ✓ | ✓ |
| 編集者 | ✓ | ✓ | — |
| 閲覧者 | ✓ | — | — |

各本棚の管理者は1名です。管理者の解除・移譲は初期版では扱いません。別の本棚では同じアカウントに異なる権限を設定できます。メンバー追加前に、相手にもアカウントを登録してもらってください。

「シリーズを管理」から本棚内のアセットを順番にまとめられます。1アセットにつき1シリーズ、最大1,000件。巻数・話数は「第1巻」「第2話」「外伝」など自由な表示ラベルで、実際の順番は矢印で設定します。シリーズを選ぶと設定順で表示され、ビューアーの前後ボタン／選択欄で移動できます。管理者・編集者が編集し、閲覧者は閲覧のみ。本棚の権限をそのまま引き継ぎます。シリーズを削除してもアセット本体・個人の続き位置・閲覧記録・暗号化ダウンロードは残ります。[シリーズ仕様・API](docs/series.md)

「連続再生・閲覧」は初期ONです。動画は実際の再生終了後に5秒の取消可能なカウントダウンを挟み、次のアセットへ進みます。本は最終ページの「次の作品 →」、下部の継続ボタン、右矢印／PageDownで次へ進めます。開いただけ・スクロール・読書時間による自動ページ送りは行いません。連続移動先は先頭から開き、動画なら自動再生を試みます（ブラウザー／端末に制限された場合は再生ボタンで開始）。通常の前後移動／作品選択では従来どおり続き位置を復元して、動画は手動再生です。切り替えごとに最新のシリーズ順・アクセス権を確認し、最後で停止します。

## 起動する

サーバーは**Dockerコンテナでも、OS上のNode.jsでも直接実行できます**。認証・共有本棚・サムネイル・ストリーミング・分割アップロードは同じ実装です。クライアント側の変更は不要です。[両方式の設定・データ切替手順](docs/run-modes.md) を用意しています。

### Dockerコンテナで起動

Docker Engine / Docker Desktop と Compose v2 が必要です。

```sh
docker compose up --build -d
```

[http://localhost:3000](http://localhost:3000) を開き、アカウントと本棚を作成します。データベース・ファイルは `mirea-data` ボリュームに保存され、コンテナの再作成後も保持されます。通常の停止は `docker compose down` です。`down -v` はデータも削除するため使わないでください。

初期設定ではPC内からだけ接続できます。Androidから使う場合は、HTTPSのリバースプロキシを通して同じサーバーに接続します。[運用メモ](docs/operations.md) を参照してください。

**自前サーバー（直接起動／コンテナ）＋Cloudflare Tunnel／Proxyを使う場合**は、[Cloudflare運用メモ](docs/cloudflare.md) を確認してください。分割転送は実装済みですが、公開Tunnelを含む通常のCDN経路には動画・大容量ファイルの利用条件があり、分割だけで本番配信の条件を満たすわけではありません。Stream等の対応サービス、DNS-onlyの別配信経路、または私設ネットワークなどの選択が必要です。

画像の本は、画像をまとめて選択して1回アップロードすると1冊になります。選択時にファイル名の数字順（1、2、10）に並べ、登録前に矢印でページ順を変更できます。先頭ページが表紙です。1冊500枚まで、画像1枚25 MiBまで・4,000万画素まで、合計サイズはアップロード上限以内です。静止画を対象とし、ページの元画像は再圧縮せずそのまま保存します。EXIFの向きは閲覧・サムネイル生成時に反映します。

サムネイルの生成を完了してから登録します。読み取れない画像・PDF・動画、暗号化PDFなどは登録を拒否し、途中の本を残しません。更新前に登録済みのPDF・動画のサムネイルは、初回表示時に生成・保存されます。

動画プレビューは本編とは別の軽量MP4です。新規動画は公開前に生成・検証し、既存動画は必要時に生成します。PCは約350msホバーしたカード、Android／タッチ端末はスクロールが落ち着いてから画面中央付近の十分見えているカードを1件だけ再生します。音声なし・最大6秒・最大480px・12fps・2 MiB以下です。初回生成中やエラー時は画像を保ち、ホバー終了・スクロール・別画面・非表示で停止します。動きを減らす設定やデータセーバーが有効な場合は自動プレビューを行いません。[動画プレビュー仕様](docs/video-previews.md)

送信が失敗したときは、同じアカウント・本棚・タイトル・ファイル（画像本は同じページ順）で再試行すると、24時間以内は受信済みの続きから送れます。画面を再読み込みした場合はローカルファイルを選び直してください。受信済み部分もハッシュで照合します。受信途中にアップロード画面を閉じると取消です。サーバー処理開始後に閉じても変換は継続し、「アップロード処理」から進捗・再試行・取消を行えます。Androidアプリを閉じている間のバックグラウンド転送は対象外です。

### Node.jsで直接起動（Docker不要）

Node.js **24.13以上の24.x** と pnpm **11.25.0** が必要です。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

`.env.example` を必要に応じて `.env` にコピーすると、保存先・アップロード上限・登録可否などを変更できます。初期上限は1コンテンツ合計2 GiB、保存先は `./data` です。`UPLOAD_CHUNK_BYTES` は1リクエストの分割サイズ（標準8 MiB）で、合計上限とは別です。低速回線では1 MiBなどへ下げられます。

直接起動ではインストール先の `.env` を読み、相対 `DATA_DIR` もインストール先を基準にします。OS側の環境変数が優先されます。停止は `Ctrl+C` です。Dockerではデータを引き続きnamed volumeへ保持し、任意でホストディレクトリ方式に切り替えられます。同じ保存先の直接起動とコンテナを同時に動かさないでください。

Linuxの直接起動ではOSの`ffmpeg`パッケージを導入してください（Debian／Ubuntu例：`sudo apt-get install ffmpeg`）。標準の`/usr/bin/ffmpeg`と`/usr/bin/ffprobe`を使い、コンテナには両方を導入済みです。同梱Linux静的版のTS入力での異常終了を避けるため、Linuxでは同梱版へ自動フォールバックしません。Windows／macOSでは依存のインストール時に同梱版を取得します。別途用意したバイナリは `FFMPEG_PATH`／`FFPROBE_PATH` で指定できます。更新された信頼できるビルドを使ってください。PDFのサムネイルには同梱PDF.js・Canvas、画像にはsharpを使います。

Web画面の開発では、APIを `pnpm start` で起動し、別のターミナルで `pnpm dev` を実行します。Viteの開発サーバーが `/api` をポート3000に転送します。

## 閲覧記録とプライバシー

通信が不安定な場所に備え、本・動画をアプリ／ブラウザー内部へ暗号化保存できます。保存はAES-256-GCMの分割データのみで、鍵は永続保存しません。保存済みでも開くたびにログイン・本棚権限をオンライン確認し、失敗時は開きません。認証後の閲覧中だけメモリー内で復号し、動画／PDFは必要範囲を取り出します。完全オフライン閲覧やDRMではありません。[暗号化ダウンロードの仕様・鍵・制限](docs/downloads.md)

アセットを開くと、前回サーバーへ保存した続き位置を自動復元します。動画の再生開始は手動です。約5秒ごと、一時停止・シーク完了・閉じる・バックグラウンド移行時に保存を試み、本棚カードにも自分の続き位置を表示します。「最初から」で戻せます。プレビューでは変更せず、分析用ログの停止中も動作します。[再開位置の仕様・競合・通信時の制限](docs/progress.md)

動画・PDF・画像の本を「アセット」として、約1秒ごとの表示／実再生区間、ページ、表示範囲、倍率、シーク・一時停止等の操作を記録します。本人は「自分の閲覧記録」で詳細と生ログを確認できます。本棚管理者・サーバー管理者に他人の個別履歴を公開するAPIはありません。匿名集計は5人以上の集計グループだけを表示し、件数・時間を丸め、当日（UTC）を除きます。少人数では何も表示しません。

生ログは期限を設けずDBに保存し、アセット削除や共有解除でも消しません。`ANALYTICS_ENABLED=false` で新規収集だけ停止できます。全体集計を見られるアカウントのUUIDは `SERVER_ADMIN_USER_IDS` に明示指定してください（初期管理者の自動付与なし）。**サーバーのDB・バックアップを直接読める運用者まで個別ログから隔離する暗号化は未実装です。** 閲覧時間は端末上の推定で、注意・読了の証明ではありません。SQLiteは大規模分析基盤ではないため、利用増加時は保存先・分析基盤の分離が必要です。[閲覧記録の仕様・保存量・権限・API](docs/analytics.md)

## Androidアプリ

Web画面をアプリに同梱するCapacitor構成です。Androidブラウザへの転送ではなく、アプリ内で本棚・アップロード・PDF・動画を利用します。サーバーは別途起動してください。

1. Android Studio 2025.2.1以上、JDK 21、Android SDK Platform 36を用意します。
2. `pnpm install --frozen-lockfile` を実行します。
3. `pnpm android:sync` を実行します。
4. `pnpm android:open` でAndroid Studioを開き、端末かエミュレーターで実行します。
5. アプリのログイン画面で、接続先のHTTPS URL（例 `https://mirea.example.com`）を入力します。

デフォルトの接続先をビルドに埋め込む場合は、`.env` に `VITE_API_URL=https://mirea.example.com` を設定してから同期します。URLはアプリから変更できます。独自ポートを含むHTTPS URLにも対応します。自己署名証明書の検証回避やHTTP通信は有効にしていません。

CLIでのデバッグAPK生成は、同期後に `android` フォルダで `./gradlew assembleDebug`（Windowsは `gradlew.bat assembleDebug`）を実行します。出力は `android/app/build/outputs/apk/debug/app-debug.apk` です。配布用にはAndroid Studioで署名鍵を設定し、署名付きAPK / AABを作成してください。

アプリの最小OSはAndroid 10（API 29）です。PDF表示のため、Android System WebViewは最新版に更新してください。セッションはタブ／WebViewのセッション領域に保存し、アプリの終了時などに再ログインが必要になることがあります。

## 構成とAPI

```text
PC Web ───────────┐
                 ├── HTTPS ── Fastify API + Web配信 ── SQLite
Androidアプリ ────┘                         └──────── ファイル領域
```

- `server/`: Node.js / Fastify、SQLite、認証、権限確認、ファイル配信
- `web/`: 日本語UI、PDF.jsビューア、動画プレーヤー
- `android/`: Androidのネイティブプロジェクト（Capacitor）
- `tests/`: 認証・共有・アクセス制御・アップロード・配信・永続化のテスト
- [API仕様](docs/api.md)、[データ設計](docs/architecture.md)、[運用メモ](docs/operations.md)
- [直接起動／コンテナ起動の設定と切替](docs/run-modes.md)

```sh
pnpm test
pnpm build
pnpm test:startup
```

現時点は単一サーバー向けの初期版です。ZIP/CBZによる画像本の登録、登録後のページ差し替え、完全オフライン閲覧、メール確認・パスワード再設定、アカウント管理画面、ウイルス検査、ストレージ利用量制限は未実装です。新規動画の本編はH.264 / AACへ変換します。更新前の動画は従来のファイルと再生方式を維持します。
